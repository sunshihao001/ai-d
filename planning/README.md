## 草案如何转为现行做法？

先以公开、可逆的知识整理任务进行试用；审查是否增加重复工作、错误授权、目标漂移或查找成本。如果有益，则保留需要的最短方法并更新状态；如果有害，撤回相应规则，保留其失败记录。重要变化可以在 GitHub PR 中提出和修订，只有确认价值的内容才合并到 main。

**当前真实状态**：这些文件只是专业规划和执行交接的候选；尚未实现自动 GitHub 同步、长期记忆或高质量跨任务认知评测。项目仓库为 Public，谨慎处理私人资料。

## 首轮情景走查与文件检查（2026-11-06）

下面是依据仓库现有内容进行的**人工方案走查**，不是独立模型 A/B 实验或自动同步功能的实跑。

| 输入情景 | 目标判断 | 应由 AI 承担的行为 | 正确交付或停止方式 |
|---|---|---|---|
| “我只会说简单想法，帮我规划这个项目” | G0 为减少专业指挥负担；G2 为当前方案收束 | 从原话提出竞争路线，检查重复建设、证据与回滚；低风险可逆步骤直接处理 | 一份有选择理由的草案，不把 AI 提案当用户已经确认的 G1 |
| “GPT 研究完要上传 GitHub，不要再乱建文件” | G2 为成果管理，G3 为存储方案 | 先查现有知识索引与原位置，再决定增补、改写、交叉引用或不提交 | 实际 GitHub 写入后回读；只有 commit/PR 与内容核对齐全才报已上传 |
| “把七月到现在所有内容直接上传” | 可能涉及保留知识与保护隐私两种目的 | 查公开性、原始资料与敏感信息，分类索引，避免复制私人聊天及版权原文 | 上传可公开的来源索引和专业综合；无法公开的内容保留在受控来源 |
| “又找到一个新 Agent 框架，是否替换现在的路线？” | 默认是 G3 实现候选，不等于 G0/G1 改变 | 检查新证据会否改变目标达成、成本或失败风险 | 可能改变决策才深入；否则留参考线索，不重建系统 |

**静态仓库核验**：在本草案分支检查 README 与五份规划文件，按当前文件树解析其中 **28 条相对链接，未发现缺失目标路径**。文件状态均标记草案或候选；不能从链接检查推断方法已提升 AI 表现。独立模型评测、跨会话自动触发、GitHub 公共链接的全部外部有效性仍未完成。

**本轮裁决**：继续保留 B（自适应规划＋可逆行动＋GitHub 草案审阅），不扩建 Agent 组织或新的权威知识目录。下一项真正有信息价值的验证，应比较两项陌生任务中“没有这些方法”和“按需使用这些方法”在目标准确性、错误、重复建档与人工返工上的差异。
