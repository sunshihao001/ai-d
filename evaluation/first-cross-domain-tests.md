# 跨领域验证总记录｜已执行局部测试与尚未执行的完整模型对照

> **状态区分（2026-11-06）**：本文件下方包含原始的独立模型对照设计（仍未执行），以及后来已执行的静态文件检索测试、原始 Issue 机制复现和21项来源适用性单元测试。**局部代码测试通过不等于 AI 已能在真实陌生任务中可靠理解、研究、决策和完成工作。**
日期：2026-11-05
## 尚未执行的独立模型对照：原始研究假设
H1：按需调用正确的目标变化/证据适用/价值排序方法，相比不给额外知识，可以增加有证据的关键问题发现和方案判断。
H2：过量注入旧流程、概念图和固定专家步骤可能提高字数与成本，降低任务贴合度；需要与基础模型和按需调用形成对照。
H3：正确记录旧目标被后续用户反馈覆盖，可减少错误继续执行；保存对话不自动等于正确运用目标关系。

## 任务选择
- 任务 A：模拟公开化的目标演化案例，从“找钱包”→“理解资金机制”→“市场智能产品”→“AI 工作方式升级”；检验能否保留原目的、识别上层战略改变、提出合理但非擅自生效的新目标。使用改写样例，**不是把用户私人聊天上传公开仓库**。
- 任务 B：不相关的开源工具选择或真实工程故障调查；检验按需方法能否找到关键未审计依赖、停止无价值的额外搜索、给出可复查行动。
- 任务 C：让旧历史信息失效的新证据；检验模型是否继续机械重复过时“必须先建 Bot/固定阶段”的结论；使用非个人的合成反例。

## 对照设计
A0：相同任务、相同工具权限、普通模型，不额外注入本项目知识。
A1：相同任务、相关专业资料按需选取（不注入一切历史）。
A2：相同任务、过量旧工作流文本注入，作为潜在负面对照。
尽量固定模型版本、可用资料时点、工具调用/成本预算；匿名评价结果，记录原始输入/输出、事实核查、用户干预、重大错误及成本。不要把同一上下文先看过一组答案后另一组称为严格独立测试；允许先做诊断，再另用新任务复核。

## 主要观察指标
1. 原始目标理解与用户明确/AI假设的区分。
2. 是否发现此前遗漏、且会改变决定的事实或问题。
3. 方案比较是否包含真正差异、证据、反例和可推翻条件。
4. 是否使用了过期知识、把旧规则当成当前强制命令。
5. 是否给出可完成的下一行动；是否及时停止低价值研究。
6. 输出对用户的负担、工具/令牌开销、安全边界与误报。
7. 最终是否真的产生比无增强方案更可靠的成果。

## 完成条件与暂停线
没有真实独立任务结果之前，所有增益陈述为假设。若只有更长输出、没有可检查的判断变化，不升级为常驻规则；若严重错误增多，立即停用产生该错误的方法。用户的重大目标和对外操作授权不能由评测程序替代。

## 2026-11-06｜静态检索诊断：为什么字面相似不足以选对知识

**完成状态：执行过一次可复述的仓库文件检索诊断，不是独立模型 A/B 测试。**
数据范围：本 Draft PR 中实际读到的 11 个 Markdown 文件（README、knowledge/INDEX、COGNITIVE-MAP、expert-concept-navigation、organization-protocol、planning 下 4 个文件、research 的目标研究、evaluation 本文），测试内容来自用户研究目标的**公开化改写**，不纳入私人原始对话正文。

### 方法
作为透明的弱基线：对每条口语提问与每份文档，提取连续中文字符序列/英文字母序列；以每序列的相邻两字符形成 bigram；逐文档计算“查询与文档的 bigram 重叠计数（取查询和文档词频较小值）”，按总分排序。同分的先后顺序按输入文件顺序，不代表优劣。不分词、不推断语义、不按文档长度归一化；它只代表一种**刻意简单的表层匹配**，并非业内生产级 BM25、向量检索或混合检索。

### 本轮实际检索输出及知识适用性复核
| 口语问题 | bigram 最高匹配（得分） | 根据该问题需要作出的判断，优先阅读什么 | 观察 |
|---|---|---|---|
| “只要把别的行业做法学过来，就能用在我这个项目吗？” | COGNITIVE-MAP 与 2026-11-05 研究报告并列（7分） | 先看 COGNITIVE-MAP 的迁移/反例，再回查 expert-concept-navigation 的跨域适用界限 | 排名能找到相关概念，但仍需区分“类比”与“直接适用” |
| “这篇文章讲得很专业，直接写成项目必须遵循的规定吧？” | README、COGNITIVE-MAP、expert-concept-navigation、goal-navigation、research-to-github **五项并列**（均5分） | 优先 organization-protocol 的证据/授权属性，以及 research-to-github 的入库/版本原则 | 词重叠无法区分“论文本身可信”与“可否转成项目指令” |
| “研究了一直没完，每天出现新想法，什么时候该停下来做事？” | 2026-11-05 研究报告（9分）；COGNITIVE-MAP（8分） | 优先 proposal-review 的规划停止条件、goal-navigation 的目标层级，再辅以信息价值研究 | 搜索报告高相关，但不能代替具体收束和行动准则 |
| “他明明说过不再做那套流程，为什么今天又推荐那套旧步骤？” | README（5分）；COGNITIVE-MAP、goal-navigation、proposal-review、historical-consolidation 等并列（4分） | 优先 historical-consolidation 的旧规则裁决、goal-navigation 的目标/授权修订 | 项目首页较高分，不代表能正确处理过时规则与目标切换 |

**本次观察**：较高的表层相似度只代表词语出现，不证明知识对问题适用，也不保证被选的文件足以给出行动方案。同义、反向陈述、跨域类比及历史冲突可能改变要读的文档。

**不能据此声称**“语义/关系检索比普通检索提高了多少准确率”。正确文档的判断是本轮研究者作出的任务分析，尚无独立评审；问题也不是在未知测试集上抽样；未实际运行第二种端到端检索器或生成模型。

### 下一步真正有识别力的对照
用相同未见任务、固定资料快照和预算，比较：
- **A**：独立模型自行选知识，无额外索引/提示；
- **B**：只提供术语和关键词扩展；
- **C**：提供按问题选择的概念关系、适用条件、反例和相应证据。

记录每组实际检索到的文件、是否引用正确证据、是否识别目标/机制、判断是否改变、重大错误与额外耗时。评价时对输出来源进行遮蔽，利用可核查事实与人工复核，不让同一输出生成者独自认证胜负。

### 对原先评测方向的修正
除了“检索有没有命中”，必须分别考察 **Retrieved（读到了吗）→ Applicable（对当前情况适用吗）→ Decision impact（改变了哪个决定）→ Verified outcome（实施后真实结果如何）**。过时知识应当测试是否被正确拒绝，而不是仅测能否回忆。

## 2026-11-06｜真实开源问题的知识适用性反例（已读取原始 Issue）

### 为什么要做这一轮
旧的16题测试主要评价“哪个内部文件排在前面”，没有评估**是否应检索**、**内库是否足以回答**、**检索结果是否与正确对象对应**。这三种缺口会让排名看似改善但实际问题继续存在。下表来自其他项目公开的原始 GitHub Issue，不是本项目研究者编造的场景；并不代表外部 Issue 的每项断言都已证实。

| 外部原始任务（实际读取） | 字面共性 | 可能的真实问题结构 | 适用的知识／正确下一步 | 来源地位与限制 |
|---|---|---|---|---|
| [LlamaIndex #18504：问 hello 也检索出高分引用](https://github.com/run-llama/llama_index/issues/18504) | RAG、retrieval、score | **用户意图／是否需要检索**：简单问候无需查领域资料 | 首先识别会话任务和检索必要性；只有需要检索时才谈阈值和重排 | 使用者询问；未在本仓库复现其整套聊天系统 |

### 实际离线复现：分数排序不能当原文档顺序
使用 #20597 公开给出的五个示例对象及按分数降序返回的五项 \`{index, score}\`，分别执行两种确定性赋值逻辑：
- **错误位置配对**：\`zip(input_nodes, ranked_scores)\` 使天气文本获得约 \`0.15830442\`；深度学习文本获得约 \`0.00653882\`。
- **原始索引配对**：\`input_nodes[item.index].score=item.score\` 使天气文本获得约 \`0.0000161876\`；深度学习文本获得约 \`0.15830442\`。
- 在独立离线 Python 数据结构测试中，四项关键断言及节点覆盖断言全部通过。**这是数据映射错误的最小复现**，不是对 LlamaIndex 当前包版本的集成测试。Hugging Face [Text Embeddings Inference API](https://huggingface.github.io/text-embeddings-inference/) 的 rerank 接口包含 \`index\` 字段，支持按照原始位置而不是任意返回顺序理解结果。

### 对冻结仓库的额外静态反例：零分也会返回一个文件
使用之前冻结的 [检索实验](retrieval-probe-results-2026-11-06.md) 的16份文件快照（\`cd51f614fc9e7672c8fcf750ddc1f8dec59f4cdd\`）检查英文查询 \`hello\`：16个文件中均不包含该独立词。既有检索代码无“无需检索／没有内库答案”的分支，即使所有分数为0，按文件路径排序仍返回 \`decisions/2026-11-05-goal-options.md\` 为第一条。

**这是实验代码的确定性边界缺陷**，不是所有 BM25 实现都这样，更不证明任何实际 GPT 必然会如此作答。其修订方向首先是允许无结果、无检索和外部取证，而不是继续增加关键词权重。

### 与旧实验的真实复核状态
通过 GitHub 连接器读取旧脚本中冻结的 \`PATHS\`、\`CASES\`、\`PARAMS\` 与仓库提交版本的16份正文，并在同一工具环境重新执行其 BM25/扩词/职责加权逻辑；结果与旧报告**逐项统计完全一致**：12题留出集的 A / B / C Top-1 分别为 \`0.333 / 0.333 / 0.583\`，Recall@3 为 \`0.500 / 0.500 / 0.750\`，MRR 为 \`0.549 / 0.531 / 0.718\`。

这证明旧结果**可按相同逻辑重新计算**；本轮并未在可联网 Git 克隆中直接执行保存的 Node.js CLI 文件（容器无法解析 github.com），因此不将其标记为“CLI 端到端重放通过”。

### 从四个案例形成的专业判断：允许不选文档
知识选择应当允许以下几种**结果**，而不是始终给出文件 top-1：
- **不需要知识检索**：问候、纯格式转换或已拥有足够上下文的任务；可直接回答。
- **当前已有知识适用**：可追溯的来源与方法满足这次问题的机制、条件、时效和对象要求；据此判断。
- **当前知识不足，需外部专业证据**：例如某软件的 API 排序语义、特定版本、具体存储更新；不要拿通用“RAG 理论”冒充源码证据。
- **关键未知尚未解决**：说明缺少的证据与下一项高价值调查；有必要时向用户询问只有用户知道的信息。

不是因为三个项目都提到“检索、更新”就给相同的修复方法。应先区分：**是否该检索、检索内容是否有效、候选是否真正适用、来源和版本是否对应、当前决策是否因此改变。**

### 后续有意义的独立验证

## 2026-11-06｜先判断证据来源：21项来源适配单元测试（已执行）

**原因**：旧的16题检索实验默认每次一定返回知识库中的文件。新增反例表明，这种强制选择可在“hello”（全部得分为0）、只润色用户提供文字、某公司当日官方公告和某特定 API 版本调查等场景返回不适当的内部文件。即使排名提高，**仍没有验证该文件能否证明当前主张**。

**本轮做的实际工作**：构造 [可执行的来源与证据适用性契约测试](source-decision-contract.test.mjs)，覆盖21个断言（18个情景＋3项不变性/反事实测试）。同类代码在独立本地 Node.js 22 测试环境运行21/21通过；GitHub 已提交版本再次读取后，在隔离 JavaScript 环境重新执行同一21项断言，21/21通过。**这是编程单元测试，不是模型认知实验。**

### 从问题出发的来源选择，而非总是选择一个文件
| 条件与测试代表 | 契约中的正确结果 | 为何不同于旧检索 |
|---|---|---|
| 简单问候、用用户提供文本润色 | `DIRECT`，无需知识库检索 | 相关文档不是必要证据 |
| 项目内已确认的目标版本 | 仅接受版本/对象匹配的内部来源 | 旧目标不再自动适用 |
| 对外公司公告、某 API 特定版本与真实运行 | 需要外部原始资料，内部通用理论不足 | 主题相关不等于有权证明当前事实 |
| 目标对象、版本或所需来源尚不明确 | `NEED_SCOPE` 或授权边界 | 不能假设最相关文档已经回答问题 |
| 同一对象、同一版本和主张出现支持/反证 | `EVIDENCE_CONFLICT` | 不得只取排名更高的支持来源 |
| 同一主张只有反证，或者支持范围不符 | `CLAIM_CONTRADICTED` 或继续取证 | 不能把相似资料强行当作支持证据 |
| 只有需要授权的私人来源 | `NEED_ACCESS_OR_INPUT` | 对话和公开搜索不可代替授权数据 |

### 最重要的适用范围
脚本**没有**自动把自然语言转换成可靠的 `requiredOrigin / subject / claimId`；这些输入由调用方显式提供。候选的 `claimRelations` 也由测试夹具人工填充，`CANDIDATE_EVIDENCE_MATCH` **不是**外部事实已经核实，更不是允许立即对外执行。有效的下一步是由 AI 面向真实问题判断来源类型，获取实际证据，再逐主张核查。

这些案例是人为构造、完全可预测的单元测试，**不能将21/21通过解释为真实问题识别准确率100%**；也不能将其与原16题的检索分数直接相减或合并。

### 成熟研究对本轮判断的限定
- [Probing-RAG (NAACL Findings 2025)](https://aclanthology.org/2025.findings-naacl.181/) 研究如何判断何时不必反复检索；并非通用证据真伪检测。
- [Self-Routing RAG (IJCNLP-AACL Findings 2026)](https://aclanthology.org/2026.findings-aacl.28/) 将内部模型知识视为多来源之一，并研究选择知识来源；不能直接声称符合本项目的所有权限与来源治理需要。
- [SURE-RAG (2026, 预印本)](https://arxiv.org/abs/2605.03534) 明确区分证据相关性与足以支持结论，并在受控数据上同时检查支持、反驳与不足；其自然幻觉检测结果存在明显边界，不能移植实验指标。
- [NIST TREC](https://trec.nist.gov/data/reljudge_eng.html) 的相关性判断描述的是检索评价，不替代来源/版本/证据充分性的审查。

### 下一轮真正需要验证的能力
从公开的陌生任务中，用**事先独立标注的真实来源需求**，检查 AI 能否从简单自然语言识别 `DIRECT / INTERNAL / EXTERNAL / UNKNOWN`，再用原始资料/代码/日志核对具体主张。必须同时统计：误用内部文件、该检索却跳过、没有授权擅自引用、证据不足却作肯定结论，以及成本和实质交付。没有真实独立评审前，该契约只作为**实验防错边界**，不升格为通用默认系统指令。

## 2026-11-06｜完整任务试验：修复 ai-d 入口与成果状态混淆（实际交付）

### 用户的普通目标与全局锚点

“研究不要只是积累文件；需要能够从整体目标进入局部专业知识，判断哪些已验证，并实际交付可用结果。”

这是一次真实仓库维护任务，但**不是陌生领域的独立模型对照**。它涉及至少四种专业视角：使用者的信息需求（人机交互）、技术文档目的与导航（Diátaxis）、目标与完成标准的可追踪性（系统工程）、主张/证据和修订（知识工程）。四种视角并非四项强制程序步骤。

### 以可核查现象而非术语开始

- 原始 [README](../README.md) 的研究与评测入口曾写“跨领域验证计划（尚未执行）”，而已有的 [静态检索结果](retrieval-probe-results-2026-11-06.md) 和 [来源契约测试](source-decision-contract.test.mjs) 已经提交；从这些入口出发可能误判所有评测都没有完成。
- [knowledge/INDEX](../knowledge/INDEX.md) 仍称一项实验是“方案（未执行）”，同时另一处已经有真实的局部试验。两者各自片段并非完全错误：**独立模型对照未执行，静态/单元测试确实已执行**。问题出在未明确区分证据层次。
- 本评测文件原始首行写“研究方案，尚未执行”，后文却列有已执行成果，读者需要翻完整篇才能判断状态。

### 三种成熟路线的实际选择

| 路线 | 优点 | 代价/反例 | 裁决 |
|---|---|---|---|
| A 重新按 Diátaxis 拆成四个文件夹、搬迁历史知识 | 面向不同信息需求组织清楚 | 对既有小仓库是一次大规模重排，产生链接与维护负担，不改善模型能力证明 | 不采用 |
| B 增建智能检索/自动路由程序 | 日后可能适合大规模资料与任务 | 目前没有证据证明自动路由比清晰入口更有价值；已有局部检索实验不能支持此大工程 | 不采用 |
| **C 修复现有入口和实验状态** | 小范围、可回退、保留全部原始知识及历史记录 | 仍需真实新使用者验证可发现性 | **本轮采用** |

### 已执行的交付和验收边界

修改了 [项目入口](../README.md)、[知识入口](../knowledge/INDEX.md) 与本文件的**当前状态标注和首轮路径**；不复制私人原始资料，不改既有概念卡与独立检索算法，不合并 `main`。验收重点是 GitHub 回读、链接是否存在、是否区分静态结果和未执行的模型实验；它能证明文件状态一致，**不能证明新读者实际使用更快或模型推理更深**。

### 对整体认知系统的反馈

当用户说“知识系统太复杂，结果还不如以前”，至少存在几个不同解释：检索没命中、知识适用不当、文件导航错误、状态陈述过时、目标/工作流约束过重。此次真实仓库证据支持**本项目存在入口和状态表述上的可维护缺陷**；并不支持断言这就是用户体验退化的唯一原因。

**下一项高价值验证**：由未参与编辑的使用者或独立模型接受一组新的口语化任务，观察其是否能在固定时间内找到需要的主文档、辨别已实测与未实测、完成可核查行动。把成功率、错误率与用户负担同原入口比较，才能检验是否实际改善了可用性。

外部依据：[Diátaxis 文档用户需求分类](https://diataxis.fr/)；[NASA 系统设计与需求验证](https://www.nasa.gov/reference/4-0-system-design-processes/)；[W3C PROV-O](https://www.w3.org/TR/prov-o/)。这些成熟方法只为问题分析提供依据，不能证明本仓库的改动已经获得同等实证效果。
