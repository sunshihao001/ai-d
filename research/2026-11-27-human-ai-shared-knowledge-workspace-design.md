用户当前主要在 ChatGPT（GPT）对话内完成研究、知识理解、专业推理、提示词优化和项目推进；以在该入口实现知识承接、检索、实际运用、成果保存与跨会话接力为现阶段产品适用条件。外部网页/工作台是同源认知展示及维护候选，不应要求人为常规工作反复切换软件、复制全文或先部署本地智能体。现有 GitHub 连接已在本会话实际读取/写入/回读；不等于新会话自动召回全部知识。ChatGPT 原生 Projects/文件/已授权应用作为现有能力基线；外部工具的 MCP/CLI/API 存在不等于 ChatGPT 当前账户、端或模式能调用，须分别核查。优先用已可访问的连接方式，未经授权不升级套餐、不公开私密知识、不安装本地软件或新建公网服务。保留其他宿主为可选未来路径，不将当前条件固定成永久架构。

## 1. 目标恢复与专家思想
根本目的仍是扩大人的实际能力、优秀智能继承与长期认知资本。网站是理解、导航、监督、调用和改进知识的可能手段，而非目标。原用户希望 UI 显示目标状态、证据、依赖、风险、决策及下一步；专家团队为按问题动态调用的专业职责，不固定人设、数量或技能配对。沿用六域/P1–P8/K1–K9/G-B-K-D-A-C-T-R跨层锚点、意图共同形成、选择性外显、知识利用验收、双向追溯、适用性、回归与真实反馈。恢复[知识索引](../knowledge/INDEX.md)、[跨层锚点](../knowledge/foundations/cross-layer-project-anchors.md)、[整体参照](2026-11-07-whole-system-benchmarks-before-component-exploration.md)、[开放自适应系统](2026-11-15-from-idea-to-open-adaptive-system.md)、[承接竞争研究](2026-11-27-knowledge-transfer-transformation-and-evolution.md)。不把旧“暂不建UI”误作禁止研究新需求，先考察成熟产品。
本轮专业职责（单AI进行综合研究，未独立调用多专家）：产品/需求（目标、用户场景、任务）；知识工程与图情（主张、对象、分类、来源、语义边与版本）；认知/学习（专家方法、经验迁移、理解负担）；交互/信息可视化（逐层披露、导航、解释、纠正）；AI/能力工程（动态上下文、技能、可调用证据）；软件/数据可靠性（同步、权限、备份、恢复、冲突）；科学方法/质量（实际结果、回归、对照）；需要时领域专业视角。依据专业问题选技能和成熟能力，不提前固定团队。人只处理重大目标/授权/费用/风险。

## 4. 完整信息架构与界面职责（候选）

|---|---|---|

| 目标与意图 | 看初始思想、已确认目标、推断候选、保持约束 | 目标版本及来源，目的/手段区分，确认状态，影响链；人可纠正和撤回 |
| 知识与关系 | 按问题/领域/阶段/证据状态定位知识，展开关联 | 稳定ID、原文、主张、来源、适用与反证、语义类型、影响/验证；全局搜索、局部关系图、反链、路径追溯；原文与综合分开 |
| 情境调用 | 理解某项知识何时使用、作用于什么对象 | 钩子：情境→对象→原因→操作→边界→证据；实际任务引用原文，不以图连线当调用 |

| 专业能力与专家 | 看专业问题缺口、可用成熟能力及真实用途 | 动态专业责任、技能/工具来源与条件、许可、输入/输出、失效边界、真实调用结果；不填虚拟专家数量 |
| 提示词与版本 | 比较总/专项提示词、作用范围、修改原因与实际状态 | 候选、验证、部署与撤回分别记录；原稿与差异、受影响钩子、回归；保留非提示词竞争方式 |
| 任务与验证 | 看真实专业成果、依据、遗漏、下一项工作 | 目标→知识→操作→产物→验收→反馈，可选择相关上下文交给AI；未执行/预算停止与完成不同 |
| 变更与决策 | 看变更影响、历史依据、哪些才需人判断 | 旧新对照、直接/必要间接依赖、保持项、反证、风险与决策授权；避免自动改变目标 |

| 外部参照与设计 | 看选型依据、完整产品比较、阶段成果 | 成熟候选、反例、验证结果、剩余缺口与退出方案；不让普通用户选等价路线 |
UI原则：按实际问题而非数据库实体列表为主导航，首页优先成果/重要变化/真正决策，深层原文、专业细节和工具轨迹按需展开。PC三栏/双栏、移动端逐层阅读；文本可搜索/复制/导出、稳定链接、状态不用颜色独自表达，键盘/无障碍、空态/错误态/未知态；用户能纠正、查看证据、理解影响。候选原型覆盖11视图，10份样本文件，非全量产品、无实时API/写操作。独立HTML通过本次对话交付，静态结构/JS语法检查通过；浏览器策略禁止页面导航，交互验收未完成。原先25章阅读页保留。
## 5. 知识共同承接与可靠性设计
人和AI共享同一经版本约束的有效知识对象，界面是阅读投影、AI通过文件/现成CLI/API/MCP等真实支持的接口按需读取。具体实现待选型。知识实体保留原件、主张、定义、方法、案例、经验、技能、决策、验收、任务、版本等区别；稳定标识、来源、适用、反证、状态、时间、影响、可验证关系以现有组织规范为基准。允许按知识性质选择承接形态（原文/摘要/案例/技能/可执行规则/动态上下文），不强制全部转数据库。自动提炼只是候选，保留原文和来源；修改既有知识须有差异及回归、权限不扩大；人可拒绝或纠正。对实际任务输出可复用承接包：目标、约束、当前版本、相关知识/钩子、原证据、专业能力、验收、未完事项；不是全文上下文注入。UI不显示私有思维过程；只显示可核验依据、决策理由及成果。
知识保全：先盘点文件/附件/原始来源/版本历史/关系/任务状态/数据库独有记录与访问权限，分清权威资产和可重建派生视图。独立于单一服务的可迁移导出+至少一个独立备份位置；隐私内容分区，备份加密，密钥单独安全管理，公开输出只经过授权筛选。可选自动化阶段保存（有价值思想/研究/转化/反馈/实际成果），版本与快照、删除保护、差异与冲突检查，失败可追踪；不保证未捕获对话、第三方删除内容或所有知识永不丢失。恢复验收用空白隔离环境核原文/附件哈希、清单/关系、历史/权限/任务状态、原始证据可读和新AI会话实际调用；记录恢复范围、失败与缺口。备份与恢复频率由风险、成本和真实需求确定，不先改现有自动任务或配置。
## 6. 设计阶段及真实验收
A 恢复目标/知识/专家思想，实查固定基线（本轮已做）；B 多路径成熟项目/源码和反例调查（本轮已做）；C 需求、信息架构、视图交互、可靠性及试用方案（本轮候选完成）；D 真实隔离样本试用与测试：复制已有知识的只读快照，不迁移主库，比较现有Markdown渲染、完整工作台与维护/调用能力，先试原生功能，再判断缺口；E 基于实际结果裁决、必要授权、逐步实施及版本化；F 真实工作、维护和回归。非永久强制研究流程。
关键验收：输入完整清单及其全部可访问资产，区分已导入/未导入/不能读/未审查；链接解析与语义关系的独立正反例；能从普通问题检索到正确钩子及原证据并实际改变任务行动；新知识/目标变化能查影响及保留项；候选不能覆盖现行指令；并发/重复导入/失败中断/回退、权限隔离、独立备份恢复、新模型接力；人以真实任务查到正确状态、理解必要知识及决策，减少负担；记录端到端时间/成本/维护。以现有宿主、公开/脱敏资料、只读隔离副本为默认试验，不将静态UI冒充这些能力已经实现。若现成产品满足需求则用，不开发重复组件；若不满足才定义最小必要补足范围。当前未完成完整外部产品运行、全语料语义梳理、独立备份恢复、AI真实调用测试或正式选型；不改AGENTS/根本目标/定时任务/主分支/业务仓库。
