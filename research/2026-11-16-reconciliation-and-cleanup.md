# 2026-11-16｜ai-d 新旧知识整合与污染清理裁决

> 状态：CURRENT RECONCILIATION / DESIGN-LEVEL / NOT_RUNTIME_VALIDATED

## 1. 本轮目标

把“外部智能吸收”接到 ai-d 已有的目标、知识、证据、能力、Runtime、领域、验证和进化体系中；同时清理会继续把系统带向“知识越多越好、结构越复杂越好”的旧倾向。

本轮不是重新设计 ai-d，也不是把新概念覆盖旧研究。原则是：

**保留有效认识 → 合并重复认识 → 降级未经验证结论 → 移除当前默认规则中的污染 → 保留必要历史溯源。**

## 2. 新知识如何与旧知识结合

| 已有资产 | 新的外部智能吸收如何接入 |
|---|---|
| P1–P8 | 继续作为问题入口；外部研究按实际问题进入，不新增 P9 |
| 知识九阶段 | 作为知识生命周期视角；外部智能吸收横跨 K2–K9，不新增 K10 |
| 组织协议 | 增加“来源职责不同、证据不混级、污染可降级/淘汰”的当前解释 |
| 跨层锚点 | Source / Knowledge / Code / Test / Runtime / Result 可以互相追溯，但不要求建 Graph |
| 能力整合 | 外部资料是 capability source；研究结果最终进入能力选择、组合、验证，而不是停在笔记 |
| Hermes | 继续复用成熟 Runtime；外部研究用于发现/评估能力，不重新造 Runtime |
| Muse | 作为可选研究/执行环境；运行结果进入 evidence，但不自动升级为知识真值 |
| GPT | 作为独立竞争解释/审查来源之一，不成为唯一裁判 |
| Blix 等领域项目 | 作为现实验证场；领域结果不得直接污染通用 ai-d 规则 |
| Verification / Evolution | 决定保留、降级、修订、替代、淘汰 |

## 3. 当前应该保留的核心认识

### 3.1 知识不是最终资产

长期资产至少区分：

- Concept：解释问题的专业认识；
- Method：可重复的研究、判断或执行方法；
- Pattern：跨来源/跨项目反复出现的机制结构；
- Capability / Skill Candidate：可以实际调用的方法；
- Evidence / Case：支持、反驳或约束主张的事实和运行结果。

Source 是入口，不是最终资产。

### 3.2 外部来源有不同职责

- X：发现最新实践、争议、失败经验、正在形成的想法。
- GitHub：检查可运行机制、源码、测试、Issue、PR、演化。
- Reddit/评论：发现真实摩擦、反例和不同意见。
- 官方文档/标准：确认协议、接口、作者定义和边界。
- Papers/Books：理论、方法、原理和长期背景。

来源之间不能简单多数投票。需要比较它们到底在回答什么问题、证据是否独立、适用条件是否一致。

### 3.3 “不会就学习”需要判断

缺事实、缺概念、缺成熟实现、缺真实证据、来源冲突、需要实验、信息价值过低，这些情况对应不同的下一步。

因此：

**Learning ≠ 永远继续搜索。**

### 3.4 真实验证优先于文档堆积

研究结果只有在真实任务中能够改变判断、减少错误、减少重复劳动、改善执行或明确暴露边界时，才有资格升级为高优先级能力资产。

## 4. 本轮明确降级/删除的旧倾向

以下内容不再作为当前默认设计：

1. 把 ai-d 做成“大而全知识库”；
2. 认为知识文件越多，系统越强；
3. 每发现一个遗漏就增加一个新阶段、专家、标签或系统；
4. 把所有历史资料全文注入长期上下文；
5. 先建 Capability Graph / Knowledge Graph / 巨型 Workflow，再等待真实任务；
6. 重复实现 Hermes 已有 Tool、MCP、Skill、Memory、Delegation、Gateway、Cron 等 Runtime；
7. 用研究轮数、来源数量、文档数量证明能力提升；
8. 用单个 X 帖子、README、作者自述或模型自评证明工程事实；
9. 把理论类比直接写成跨领域工程规则；
10. 把一次成功案例固化成永久规则；
11. 把“已经保存到 GitHub”误写成“AI 已经学会”；
12. 把 AI 自己提出的候选目标写成用户已经批准的长期目标。

这些不是说历史文件“全部错误”。它们是**当前默认权威被撤销的设计倾向**。

## 5. 为什么不直接删除所有旧研究文件

删除历史文件会同时删除：
- 旧判断为什么成立；
- 后来为什么改变；
- 原始来源；
- 反例；
- 尚未解决的问题。

因此本轮采用“**当前入口删除权威 + 历史文件保留溯源**”。

后续如果文件经过逐项检查确认：
- 没有独立来源；
- 没有独立机制；
- 没有反例/决策背景；
- 没有当前或历史引用；
- 与其他文件完全重复；

再执行文件级删除。

这比一次性清空历史更不容易产生新的知识污染。

## 6. 当前 ai-d 的最小认知闭环

**真实目标 → 发现未知/能力缺口 → 选择合适外部来源或已有能力 → 理解与比较 → 应用 → 验证 → 保留/降级/淘汰 → 影响下一次能力选择。**

它是设计关系，不是要求每次任务按固定顺序执行。

## 7. 当前禁止过早固化

以下都暂不作为工程必做：

- Capability Graph；
- Knowledge Graph；
- 自动 Source→Skill 编译；
- 大型知识数据库；
- 新 Agent 层；
- 新专家委员会；
- Hermes core 重写；
- 全自动持续研究；
- 统一所有领域的数据模型。

真实任务证明缺口后再决定。

## 8. 当前验证任务

下一步不再继续写同义理论。

选择一个真实、可验收、与 Solana 不同的任务，对照：

A. 普通搜索/总结；

B. 外部智能吸收：来源分工 → 证据 → 方法/模式 → 应用 → 验证 → 修订。

比较：
- 事实准确性；
- 关键未知发现；
- 错误迁移；
- 用户纠错次数；
- 重复研究量；
- 工具/模型调用量；
- 最终交付质量；
- 能否留下真正可复用的经验。

若 B 没有稳定优势，停止扩张该设计。

## 9. 当前结论

ai-d 当前最值得建设的不是更多“知识”，而是：

> **知道外部世界哪里已经有好东西；知道什么值得学习；知道哪些只是观点；知道如何把它转化成方法、能力和项目判断；知道什么时候应该验证、降级或删除。**

这成为外部智能吸收层与已有 ai-d 体系的共同交汇点。
