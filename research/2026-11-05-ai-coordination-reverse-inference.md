# 2026 AI 研究逆向推演：ai-d 的目标、认知机制与工作流边界
日期：2026-11-05｜性质：多轮外部资料研究＋跨领域综合推论｜状态：研究结论，不是已运行的软件或已经提升的模型能力。

## 0. 先说结论
ai-d 不宜只是一套提示词、行业知识汇编，也不宜一开始就构建一个包揽全部工作流的 Agent 操作系统。更有价值的方向是研究一组可验证、可修正、可按任务调用的“人机目标与专业判断机制”，并通过真实案例检验其跨场景迁移，然后按需封装为 Skill、资源、工具或 Agent Runtime 的适配层。

最重要的新认知：**目标、知识、工作状态、执行权限，是不同类型的信息**。用户目标可以演化；旧知识可能失效；执行状态需要可靠持久化；重大授权不能从历史描述自行推断。将这四种信息混在一起会让“知识越多、越自主”变成负资产。

## 1. 本轮实际问题
反向从 2025—2026 的人机协作、动态目标推理、长期记忆、元推理、Agent 执行与评测研究出发，问：
- 不预设“内核＝一套固定 Agent 工作流”时，ai-d 可以有哪些更成熟的目标？
- 哪些能力属于可迁移的认知方法，哪些只是具体运行环境的基础设施？
- 什么情况下继续扩展研究，什么情况下应该停止并交付？
- 怎样验证“让 AI 少问、多做、多发现方向”确实改善真实任务而没有造成目标漂移？

## 2. 第一轮：目标、主动性与人机协作
**证据**：
- IEEE RA-L（2026）研究了人机任务进行时的目标变化检测；场景为协作烹饪机器人，**不能直接证明 LLM 工程系统能可靠识别个人长期目标**。https://ieeexplore.ieee.org/document/11299413/
- AAAI 2026 的 La VIDA 是关于目标失效后自动目标形成的研究摘要，证据主要来自特定实验环境，不能直接移植成自由目标修改权。https://ojs.aaai.org/index.php/AAAI/article/view/41367
- 2026 人机协作研究中，目标一致对主观合作体验指标有重要影响（182 人实验）；不等于所有任务只要提高自主性就提高最终质量。https://www.sciencedirect.com/science/article/pii/S2949882125001306
- Value of Information: A Framework for Human-Agent Communication（2026 年 1 月预印本）将“是否向人提问”视为信息价值与用户打断成本的权衡。https://arxiv.org/abs/2601.06407

**本轮推演**：
1. 意图识别只是局部：用户说“找赚钱钱包”可能是某长期目标的一个临时实现假设，后来改变的是研究对象、产品策略，也可能是协作模式。不能把每句新想法当成彼此独立的任务。
2. 目标演化需要“来源—层级—关系—权限”：原始用户目标、AI 提出的候选目标、已被确认的目标、被证据否定的实现路径，应该分开；扩展、替代、合并、暂停与推翻不是同一动作。
3. 人的认知负担是重要成本。AI 不该每步问确认，也不能擅自替人选择重大价值目标。关键提问的收益必须超过打断成本；付费、外部发布、删除、交易和授权另有硬边界。
4. 研究质量不等于每次都产出新方向。真正的主动性还包括拒绝无价值的新目标、返回执行、适时停止。

## 3. 第二轮：知识、记忆与认知修订
**证据**：
- ACL Findings 2026 Memora：评估 remembering/reasoning/recommending，并惩罚使用已失效记忆；多个测试系统出现旧记忆复用问题。https://aclanthology.org/2026.findings-acl.1337/
- STALE（2026 预印本）研究后续观察如何隐式否定旧记忆；结果显示“检索到新证据”和“据此改变行动”之间存在明显缺口。https://arxiv.org/abs/2605.06527
- ACL Findings 2026 Task Matters：不同任务对外部上下文和模型既有知识的依赖不同；反复强调文内证据未必提高所有任务的效果。https://aclanthology.org/2026.findings-acl.202/
- EMNLP 2026 TAME 研究长期经验复用可能降低某些可信表现，并提出对经验贡献进行评估。局部实验结论不能当成跨所有模型的通用保证。https://aclanthology.org/2026.emnlp-main.2100/
- Anthropic 2025 Context Engineering 工程实践强调选择进入当前模型上下文的信息。https://www.anthropic.com/research/effective-context-engineering-for-ai-agents

**本轮推演**：
- ai-d 最有价值的不是“尽可能长的永久提示词”，而是研究知识适用性：来源与证据、条件、时效、反例、任务相关度、新旧冲突和如何拒用。
- “写进 GitHub”只表示持久保存；“当前模型读到”是检索/上下文问题；“正确使用并改善决策”是独立的实验问题。三者不得混同。
- 历史原文保留为来源，历史规则不自动变成新工作指令；允许保留多个竞争解释，而不是强行合成一个确定结论。
- 经验应按具体问题和具体证据原位修正；不能用“多专家投票”替代认知冲突裁决。

## 4. 第三轮：元推理、搜索与研究创新
**证据**：
- Inference-Time Budget Control for LLM Search Agents（2026 预印本）：在若干多跳问答基准上，用行动级 VOI 与预算权衡选择检索、拆解或提交答案。该实验不是跨所有开放研究任务的通用最优算法。https://arxiv.org/abs/2605.05701
- Beyond Final Scores（2026 预印本）：7 个模型、36 项长周期研发任务，发现其更擅长组合既有工程方法，真正方法创新少，经验可正向或负向迁移。https://arxiv.org/abs/2608.13417
- Anthropic Building Effective Agents：建议采用满足任务要求的最简单模式；工作流预定代码路径与 Agent 动态决策路径存在不同取舍。https://www.anthropic.com/engineering/building-effective-agents

**本轮推演**：
- “继续研究”必须考虑新增信息会否改变决定；搜索数量、论文数量和新概念数量不是目标。
- AI 的下一步主动推演应提供新增认识、竞争新方向、优先级、可推翻条件与明确的动作；在证据足够时也要能够说“没有值得新增的方向”。
- 探索/交付并不是两种固定 Bot，而是同一个项目要不断平衡的资源配置判断。
- 关键质量问题：AI 会不会因为“每轮都要创新”而偏离原目的？应测试无新价值时正确停止。

## 5. 第四轮：成熟工作流组件与运行时
**证据/文档**：
- OpenAI Agents SDK：Agent、tool、handoff、guardrail、session、HITL、trace 是成熟组件。https://openai.github.io/openai-agents-python/
- LangGraph persistence / interrupt：检查点、长记忆存储和暂停恢复是独立职责。https://docs.langchain.com/oss/python/langgraph/persistence 与 https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/interrupts.mdx
- MCP 2026-07-28：tools、resources、prompts 与 transport/discovery。https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/docs/2026-07-28/learn/architecture.mdx
- A2A 1.0：独立 Agent 之间能力发现、任务协作与信息交换。https://a2a-protocol.org/dev/specification/
- Agent Skills 规范：SKILL.md 与按需递进加载。https://github.com/agentskills/agentskills/blob/main/docs/specification.mdx

**本轮推演**：
- 这些成熟基础设施主要回答“如何运行、调用、路由、恢复”；ai-d 研究的差异点在于“为什么这个目标值得做、什么时候用什么知识、如何被反证改变、什么时候向人询问、怎么证明改进”。
- MCP、Skill、A2A、Agent SDK **不是互斥替代品**：它们分别涉及工具/资源互通、任务说明与参考知识包装、独立 Agent 协作和执行运行时。不能以某个组件支持 Tools 就称其解决目标演化。
- 内核不应绑死某个模型或框架。将经验证的专业方法以可阅读参考资源保存，再按场景选择 Skill、MCP resource、直接文件检索或 SDK 接入。

## 6. 汇总：目标应该怎样重新定义？
初步原定位“通用 AI 认知知识内核”正确但偏静态，容易只保存概念，忽视目标变化和行动选择。

更完整的 **ai-d 候选定位 V0.2**：
> 一个可追溯、可反证、可跨任务验证的人机目标协同与专业判断知识研究项目；研究如何从人的朦胧想法形成、修订和选择目标，主动获取适用知识，比较成熟路径，在权限内执行与验收，并从真实结果中生成下一轮高价值研究和行动。未来可被不同模型、Skill、工作流和 Agent 运行时按需复用。

本次**不直接替换 README V0.1**；候选 V0.2 需要经实用性测试及用户重大方向选择。见 decisions/2026-11-05-goal-options.md。

## 7. 全局与局部区分
**全局共同问题**：目标变化、证据的适用与失效、有限资源下的行动选择、人类价值决定权、结果与反馈、跨任务可复用性。
**局部行业问题**：Meme 市场的资金追踪、代码项目的 GitHub CI、法律或健康等领域具体规则与风险；这些需要独立行业资料及工具，不应被 ai-d 的通用方法直接替代。
**工程运行问题**：队列、调度、沙箱、工具权限、事件日志、真实存储和长时运行；由工作流产品或成熟 SDK 实现，ai-d 可研究其选型条件和故障机制，而非重造全部。

## 8. 本轮仍未证明
- 没有做跨领域、对照预算的独立模型 A/B；不能宣称 ai-d 已提升 GPT 的推理能力。
- 没有运行 Agent SDK、LangGraph 或 A2A/MCP 新协议示例；官方文档的功能陈述不是我们自己的运行验收。
- 关于“目标管理内核比传统知识库更优”是跨证据综合后的**产品研究假设**，可被真实任务结果推翻。
- 仓库公开，不能无审查上传历史私人对话、个人资料或有版权限制的原始材料。

## 9. 下一步主动推演（信息价值排序）
**首选**：用两个不同任务对比“不加载 ai-d 知识 / 选择性调用有关方法”，检验目标理解、关键未知发现、过期知识处理、研究成本和结束后的高价值下一步。先从用户原有 Solana 目标演化（仅公开化抽象材料）与新的通用软件研究场景比较。
**第二**：检查知识/目标冲突处理与用户授权规则在真实多轮任务中的反例，优先修正错误的选取/检索而非新造系统。
**第三（条件）**：只有证据证明跨工作流接入确有价值，才做 Skill 包和 MCP 资源适配。
**暂缓**：固定专家制度、多 Bot 群、通用 Agent 操作系统、大型数据库知识图谱、复杂 UI。

**最大的新认识**：ai-d 的稀缺能力可能不是“拥有通用知识”，而是“在变化中的目标和不完全证据下，正确判断下一步值得知道什么、值得做什么、该不该改变方向”。这是待跨领域验证的假设，而非已实现的算法。
