## 一、先从人的原始问题而不是软件范畴重新出发

可恢复的 2026 年 7–8 月用户表述至少含：① 自己只需不专业的简单表达，AI 帮忙理解、转为专业概念、发现未想到的知识；② 能对专家的认知结构、研究方法、判断与不同能力进行深入学习和利用，而不只借专家名义回答；③ 让 AI 辅助人的长期学习、实际工作、项目/产品构建、经济机会与自主发展；④ 同时积累知识，持续追溯来源、吸收新信息，不因历史过时知识和框架束缚而退化；⑤ 人不需先学会设计/编程再指导 AI，但涉及长远目的、资源与重大现实后果时仍保留决定权；⑥ 借成熟系统形成现实交付，而非停在研究词汇或方案。

这些不是六个新的固定模块，而是**对整体价值的六种描述**。不能只把它们翻译为“自然语言→Skills→MCP→工作流”，也不能只称作“外挂大脑”而关闭其他可能。

一个更忠实的开放性表述：研究并实践“AI 怎样在不同领域增强人与 AI 共同解决问题的能力，同时支持人的理解、判断、成长、实际行动及长期自主性”；这是一项方向性解释，**不是新官方口号或排他性产品定义**。

## 四、项目出现的“污染”是什么？有什么证据？哪些仍是猜测？

**项目内可观察现象：**
1. 2026-11-05 的 README、INDEX 和评测文档已经明确“不建固定架构”“需要 A/B”“不要将存储当能力”；然而每次新研究又新增方法分类、附加对照设计和下一轮建议。
2. 2026-11-07 研究重心迅速从完整人机能力目标，移向 Hermes 目标循环、再移向 Skills 与 MCP；这条“持续推进”是历史助手与用户的交互产物，不能自动当成独立的高价值新方向。
3. 用户说“配合不同项目的技能，形成工作流”，助手进一步提议“固定 Bundle 与动态技能发现 A/B”为下一轮主课题，属于**从一个合理的实现观察跳跃为总研究优先级**，推导尚不充分。
4. 项目当前可审到的 GitHub 是 11 月研究浓缩版，不足以确认七八月原始认知完整保留；“历史已有链接”不能代替认真恢复原始上下文。
5. GitHub 的 evaluation/first-cross-domain-tests.md 同时记载真实源码案例、离线控制分支和大量 NOT_RUN 的模型对照。**不能误写成“完全没有实际成果”，也不能称“ai-d 对用户能力已形成可测提升”。**

**机制解释候选（尚未作为因果事实证明）：** 历史 AI 答案被提升为项目权威、检索时的语义锚定、目标/手段混淆、文档产量作为完成代理指标、框架扩展的自身奖励、上下文压缩导致原始目标表达被覆盖、缺少现实任务反馈。已有事实足以要求纠偏，但不足以确定是哪一种认知机制占主因。不要以“功能固着/路径依赖”等名词替代分析。

**为什么“我们没有强制规则”也无效？** 显性规则不强制，只能避免某些直接门禁；若知识入口、文件标题、链接推荐和后续问题选择总把 AI 送回同一类资料，事实上的研究边界仍可能收缩。此项为根据连续研究记录的解释性推论，并非模型运行统计。

## 五、独立外部理论如何改变全局理解

**A. 系统整体而不是零件叠加。** Douglas Engelbart 1962 [Augmenting Human Intellect](https://www.dougengelbart.org/pubs/augment-3906-Framework.html)：个人能力应连同语言、方法、工具、训练及其相互作用审视。不能用“用了更多 Skill/Agent/文档”代替“人机整体更有效”。

**B. 人机协同并非必然叠加增益。** [Nature Human Behaviour 2024 预注册荟萃分析](https://www.nature.com/articles/s41562-024-02024-1) 汇总 106 项实验/370 个效应量；平均人机组合低于表现最好的单方（Hedges' g = -0.23），但高于人类单独表现的平均结果。任务类型和相对能力影响结果。提示不能默认“多个系统、多专家、多模态=更强”。

**C. 借 AI 完成与真的学会不能合并。** [Wiles 等，Nature Human Behaviour 2026-10](https://www.nature.com/articles/s41562-026-02566-6) 对 487 位管理咨询人员进行随机实验：有 AI 辅助时跨领域任务表现改善，但无证据表明移除 AI 后已掌握相应技术知识。与 [Contractor/Reyes IZA 2026-07 RCT](https://www.iza.org/index.php/publications/dp/18792/experimental-evidence-on-the-learning-impact-of-generative-ai) 合并阅读：后者在特定学习任务发现 AI 可能改善知识测试，尤其在用于解释而非代写时。**不应抽象为“AI 一定降低学习”或“一定提高学习”。**

**D. 长期记忆并非自动等于长期理解。** [LongMemEval ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/d813d324dbf0598bbdc9c8e79740ed01-Abstract-Conference.html) 用 500 个跨会话问题考察提取、跨会话推断、时间判断、知识更新和拒答；一般记忆系统有显著衰减，但任务相关索引、检索与阅读设计可改善。该结果不能证明 ai-d 的历史目标召回已经可靠。

**E. 真实工作的多步骤执行是独立难题。** [TheAgentCompany NeurIPS 2025](https://proceedings.neurips.cc/paper_files/paper/2025/hash/0d744742f6fac4d1134c019b7cef3c8a-Abstract-Datasets_and_Benchmarks_Track.html) 的模拟公司环境中其最优基线仅自主完成约 30% 任务；[OSWorld 2.0](https://github.com/xlang-ai/OSWorld-V2) 研究长时计算机操作的状态恢复、跨来源推断等失败。它们不是 Hermes/ChatGPT 用户端成功率，但反驳“有工具链就具备长期全自主成品能力”。

**F. 人类专家知识/软件知识维护各有成熟参照。** [Meta Organizational Second Brain](https://engineering.fb.com/2026/09/02/ml-applications/organizational-second-brain-ai-learns-from-experts/) 提供将知识缺失与方法失误区分并纠正的内部实践；[OpenWiki](https://github.com/langchain-ai/openwiki) 更适合代码主张与版本维护。均不能代表已经实现全部通用专业认知。

## 六、旧研究不应一律废弃：逐项重新定级

**应保留的研究资产：**
- 用户从简单表达走向专业理解、在错误表达中发现正确问题的原始目标；
- 七八月专家问题表征、知识来源溯源、跨领域关联、学习与现实验证；
- 旧知识不能靠长系统提示词强制灌输，必须允许检索、冲突、时效、权重变化；
- 对开放未知、反证、不同领域机制和经济/实际行动价值的研究；
- 有真实仓库 SHA/原始材料、控制分支或实际 GitHub 写入/回读的案例；
- 成熟项目、论文、经典书籍和失败记录，作为来源入口而非软件依赖；
- 理论互证可以支持**低风险阶段性决策**，无需每个概念都先完成大型实验，但不得冒称真实效果。

**应降级为“历史方案 / 仅在条件满足时使用”的内容：**
- 固定专家人数与无限角色委员会；T00/T02/分类图谱/多门禁是当时方案不是原始愿景；
- 所有问题默认遵循 P1–P8、统一研究轮次、相同结尾模版；
- 因已研究某个 Agent 就以其为唯一主体或必须接入；
- 因已经整理 Skill 标准就以 Skill 组合为独立总课题；
- 不分场景地强制复杂 A/B、强制所有知识都实跑，或相反以理论相符就认定现实能力已经获得；
- GitHub 文档数量、新目录、统一术语数量成为进度指标。

**应明确 UNKNOWN：** 全量早期原始信息是否已恢复、跨领域认知净增益、面向真实普通用户的长期成本/稳定性、真实外部 Agent 集成效果、长期人类学习效果与规模化商业价值。

## 七、对“整体产品是什么”的重新开放判断

不急于选择唯一成品。可能的产品结果至少有：一个自然语言研究伙伴、一个跨项目任务执行工作台、一个按需调用的专业知识与判断来源、一个帮助用户学习/择业/完成现实问题的长期支持系统，或这些能力在不同任务中有选择地出现。

这些不是要同时建立四个产品；而是由**现实问题与现成能力**决定哪些需要实际存在。ai-d 可保持来源与研究仓库，不必本身成为所有结果的软件主体；也不必承诺永远只做知识仓库。

**新的关键未解问题**：一套系统如何让不懂专业术语的人拥有真正更大的选择范围，而不是让其只能在 AI 预先给出的功能菜单里选择？这要求专业问题重构、未知发现、可行选项扩展、真实限制发现与人对价值/授权的控制同时参与，属于最初目标但不能由 Tool Search 独立解决。

## 八、用三个具有不同成功条件的完整任务检验，而非把一个案例当全项目

### 场景 1：陌生现实专业知识与人的学习

普通人说“我要学一个完全不懂的工作，帮我弄懂并避免明显错误”。AI 恢复其目标和环境限制，基于原始教材/技术资料解释概念，区分自己能做的研究和现场必须由专业人士确认的操作，给出可实际核对的学习成果。观察：无术语表达→专业理解、正确性、用户是否真正掌握关键概念、安全边界，而非只是自动产出长教程。

### 场景 2：复杂专业项目与证据型执行

普通人说“继续已有研究，选择成熟参考项目，把真正有价值的内容做成可检查结果”。使用**公开、只读**的 Solana Meme 或软件研究实例；评估 AI 是否恢复项目长目标、识别项目间可复用机制、找到源码/数据的错误前提、准确区分真实已跑与未跑、产生可检查文件或分析；不能因工具支持就启动交易/签名/付款。

### 场景 3：开放选择与长期能力发展

普通人说“我不懂未来走哪条路，让 AI 帮我找到实际可选的方向并逐步推进”。AI 不能一律套在行业产品比较上；还需要分析目标、成本、时间、技能前提、外部机会和失败风险，在有限行动后重新评估方向；用户价值选择不能由 AI 静默取代。观察是否真扩大了可理解的选择范围，是否在不依赖 AI 时也提升了某些判断。

三例分别检验：**学习/安全、专业交付/研究、决策/发展**。若只测其中任一，会遗漏项目重要目标。它们是候选验证场景，暂未完成真实对照；已有源码研究可作非独立训练案例。

## 九、按真实价值重新选择工作，不等于再提出一套阶段制度

当前可马上使用的成果：GitHub 中已经有可信原始来源、部分真实源码控制测试、经验规则与典型失败；成熟执行平台也已经存在。因此应继续使用现有 GPT+GitHub 能力完成授权范围内的真实工作，复杂任务则按需比较整套成熟产品；不先重造记忆、调度或 Skill 架构。

需要补的第一块不是再做技术清单，而是**原始目标的可追溯性**：用真正的七八月用户原文对照后来 AI 术语与 GitHub 总结，确认哪些被遗漏/误改。这项审计在本轮仅有可恢复历史摘要，不能假装原文已全取。

需要补的第二块是**跨领域实际价值**：至少一项现实学习/选择任务与一项专业交付任务，各有可核查结果。基线应包括“无附加知识的方法”“按需借用 ai-d 研究”“过量旧规则”的差异；实测不必每轮全做，更不应妨碍已经足够有依据的低风险实践。

第三块是**市场与成熟产品发现**：不限定 Hermes/OpenHuman/OpenWiki。按完整用户活动链寻找并检验成熟产品，只有确认现成品无法承载实际场景，才独立实现缺口。

**停止/重新打开研究的条件**：一次研究已提供能够改变当前选择的明确认识和可用交付，或者余下不确定项无法通过当前工具/授权解决时，停止该局部研究；但**不据此关闭上层长期探索**。遇到新的现实任务、相矛盾的证据、或重大产品变化时重新打开。

## 十、本报告对既有 GitHub 的影响范围

- 本报告是对截至目前研究过程的独立批判记录，**不是覆盖现有 README 的新版宣言**。
- 2026-11-07 研究报告 V0.3/V0.4 的 Hermes/Skills 方向应理解为**局部技术研究候选**，不是用户已确认的项目主线。
- 知识库中存在的实证、反证和有用方法仍可继续取用；只剥离将方法当作强制框架的推论。
