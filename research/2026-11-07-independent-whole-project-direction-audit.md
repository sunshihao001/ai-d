## 一、先从人的原始问题而不是软件范畴重新出发

可恢复的 2026 年 7–8 月用户表述至少含：① 自己只需不专业的简单表达，AI 帮忙理解、转为专业概念、发现未想到的知识；② 能对专家的认知结构、研究方法、判断与不同能力进行深入学习和利用，而不只借专家名义回答；③ 让 AI 辅助人的长期学习、实际工作、项目/产品构建、经济机会与自主发展；④ 同时积累知识，持续追溯来源、吸收新信息，不因历史过时知识和框架束缚而退化；⑤ 人不需先学会设计/编程再指导 AI，但涉及长远目的、资源与重大现实后果时仍保留决定权；⑥ 借成熟系统形成现实交付，而非停在研究词汇或方案。

这些不是六个新的固定模块，而是**对整体价值的六种描述**。不能只把它们翻译为“自然语言→Skills→MCP→工作流”，也不能只称作“外挂大脑”而关闭其他可能。

一个更忠实的开放性表述：研究并实践“AI 怎样在不同领域增强人与 AI 共同解决问题的能力，同时支持人的理解、判断、成长、实际行动及长期自主性”；这是一项方向性解释，**不是新官方口号或排他性产品定义**。

## 四、项目出现的“污染”是什么？有什么证据？哪些仍是猜测？

**项目内可观察现象：**
1. 2026-11-05 的 README、INDEX 和评测文档已经明确“不建固定架构”“需要 A/B”“不要将存储当能力”；然而每次新研究又新增方法分类、附加对照设计和下一轮建议。
2. 2026-11-07 研究重心迅速从完整人机能力目标，移向 Hermes 目标循环、再移向 Skills 与 MCP；这条“持续推进”是历史助手与用户的交互产物，不能自动当成独立的高价值新方向。
3. 用户说“配合不同项目的技能，形成工作流”，助手进一步提议“固定 Bundle 与动态技能发现 A/B”为下一轮主课题，属于**从一个合理的实现观察跳跃为总研究优先级**，推导尚不充分。
4. 项目当前可审到的 GitHub 是 11 月研究浓缩版，不足以确认七八月原始认知完整保留；“历史已有链接”不能代替认真恢复原始上下文。
5. GitHub 的 evaluation/first-cross-domain-tests.md 同时记载真实源码案例、离线控制分支和大量 NOT_RUN 的模型对照。**不能误写成“完全没有实际成果”，也不能称“ai-d 对用户能力已形成可测提升”。**

**机制解释候选（尚未作为因果事实证明）：** 历史 AI 答案被提升为项目权威、检索时的语义锚定、目标/手段混淆、文档产量作为完成代理指标、框架扩展的自身奖励、上下文压缩导致原始目标表达被覆盖、缺少现实任务反馈。已有事实足以要求纠偏，但不足以确定是哪一种认知机制占主因。不要以“功能固着/路径依赖”等名词替代分析。

**为什么“我们没有强制规则”也无效？** 显性规则不强制，只能避免某些直接门禁；若知识入口、文件标题、链接推荐和后续问题选择总把 AI 送回同一类资料，事实上的研究边界仍可能收缩。此项为根据连续研究记录的解释性推论，并非模型运行统计。

## 五、独立外部理论如何改变全局理解

**A. 系统整体而不是零件叠加。** Douglas Engelbart 1962 [Augmenting Human Intellect](https://www.dougengelbart.org/pubs/augment-3906-Framework.html)：个人能力应连同语言、方法、工具、训练及其相互作用审视。不能用“用了更多 Skill/Agent/文档”代替“人机整体更有效”。

**B. 人机协同并非必然叠加增益。** [Nature Human Behaviour 2024 预注册荟萃分析](https://www.nature.com/articles/s41562-024-02024-1) 汇总 106 项实验/370 个效应量；平均人机组合低于表现最好的单方（Hedges' g = -0.23），但高于人类单独表现的平均结果。任务类型和相对能力影响结果。提示不能默认“多个系统、多专家、多模态=更强”。

**C. 借 AI 完成与真的学会不能合并。** [Wiles 等，Nature Human Behaviour 2026-10](https://www.nature.com/articles/s41562-026-02566-6) 对 487 位管理咨询人员进行随机实验：有 AI 辅助时跨领域任务表现改善，但无证据表明移除 AI 后已掌握相应技术知识。与 [Contractor/Reyes IZA 2026-07 RCT](https://www.iza.org/index.php/publications/dp/18792/experimental-evidence-on-the-learning-impact-of-generative-ai) 合并阅读：后者在特定学习任务发现 AI 可能改善知识测试，尤其在用于解释而非代写时。**不应抽象为“AI 一定降低学习”或“一定提高学习”。**

**D. 长期记忆并非自动等于长期理解。** [LongMemEval ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/d813d324dbf0598bbdc9c8e79740ed01-Abstract-Conference.html) 用 500 个跨会话问题考察提取、跨会话推断、时间判断、知识更新和拒答；一般记忆系统有显著衰减，但任务相关索引、检索与阅读设计可改善。该结果不能证明 ai-d 的历史目标召回已经可靠。

**E. 真实工作的多步骤执行是独立难题。** [TheAgentCompany NeurIPS 2025](https://proceedings.neurips.cc/paper_files/paper/2025/hash/0d744742f6fac4d1134c019b7cef3c8a-Abstract-Datasets_and_Benchmarks_Track.html) 的模拟公司环境中其最优基线仅自主完成约 30% 任务；[OSWorld 2.0](https://github.com/xlang-ai/OSWorld-V2) 研究长时计算机操作的状态恢复、跨来源推断等失败。它们不是 Hermes/ChatGPT 用户端成功率，但反驳“有工具链就具备长期全自主成品能力”。

**F. 人类专家知识/软件知识维护各有成熟参照。** [Meta Organizational Second Brain](https://engineering.fb.com/2026/09/02/ml-applications/organizational-second-brain-ai-learns-from-experts/) 提供将知识缺失与方法失误区分并纠正的内部实践；[OpenWiki](https://github.com/langchain-ai/openwiki) 更适合代码主张与版本维护。均不能代表已经实现全部通用专业认知。

## 六、旧研究不应一律废弃：逐项重新定级

**应保留的研究资产：**
- 用户从简单表达走向专业理解、在错误表达中发现正确问题的原始目标；
- 七八月专家问题表征、知识来源溯源、跨领域关联、学习与现实验证；
- 旧知识不能靠长系统提示词强制灌输，必须允许检索、冲突、时效、权重变化；
- 对开放未知、反证、不同领域机制和经济/实际行动价值的研究；
- 有真实仓库 SHA/原始材料、控制分支或实际 GitHub 写入/回读的案例；
- 成熟项目、论文、经典书籍和失败记录，作为来源入口而非软件依赖；
- 理论互证可以支持**低风险阶段性决策**，无需每个概念都先完成大型实验，但不得冒称真实效果。

**应降级为“历史方案 / 仅在条件满足时使用”的内容：**
- 固定专家人数与无限角色委员会；T00/T02/分类图谱/多门禁是当时方案不是原始愿景；
- 所有问题默认遵循 P1–P8、统一研究轮次、相同结尾模版；
- 因已研究某个 Agent 就以其为唯一主体或必须接入；
- 因已经整理 Skill 标准就以 Skill 组合为独立总课题；
- 不分场景地强制复杂 A/B、强制所有知识都实跑，或相反以理论相符就认定现实能力已经获得；
- GitHub 文档数量、新目录、统一术语数量成为进度指标。

**应明确 UNKNOWN：** 全量早期原始信息是否已恢复、跨领域认知净增益、面向真实普通用户的长期成本/稳定性、真实外部 Agent 集成效果、长期人类学习效果与规模化商业价值。

## 七、对“整体产品是什么”的重新开放判断

不急于选择唯一成品。可能的产品结果至少有：一个自然语言研究伙伴、一个跨项目任务执行工作台、一个按需调用的专业知识与判断来源、一个帮助用户学习/择业/完成现实问题的长期支持系统，或这些能力在不同任务中有选择地出现。

这些不是要同时建立四个产品；而是由**现实问题与现成能力**决定哪些需要实际存在。ai-d 可保持来源与研究仓库，不必本身成为所有结果的软件主体；也不必承诺永远只做知识仓库。

**新的关键未解问题**：一套系统如何让不懂专业术语的人拥有真正更大的选择范围，而不是让其只能在 AI 预先给出的功能菜单里选择？这要求专业问题重构、未知发现、可行选项扩展、真实限制发现与人对价值/授权的控制同时参与，属于最初目标但不能由 Tool Search 独立解决。

## 八、用三个具有不同成功条件的完整任务检验，而非把一个案例当全项目

### 场景 1：陌生现实专业知识与人的学习

普通人说“我要学一个完全不懂的工作，帮我弄懂并避免明显错误”。AI 恢复其目标和环境限制，基于原始教材/技术资料解释概念，区分自己能做的研究和现场必须由专业人士确认的操作，给出可实际核对的学习成果。观察：无术语表达→专业理解、正确性、用户是否真正掌握关键概念、安全边界，而非只是自动产出长教程。

### 场景 2：复杂专业项目与证据型执行

普通人说“继续已有研究，选择成熟参考项目，把真正有价值的内容做成可检查结果”。使用**公开、只读**的 Solana Meme 或软件研究实例；评估 AI 是否恢复项目长目标、识别项目间可复用机制、找到源码/数据的错误前提、准确区分真实已跑与未跑、产生可检查文件或分析；不能因工具支持就启动交易/签名/付款。

### 场景 3：开放选择与长期能力发展

普通人说“我不懂未来走哪条路，让 AI 帮我找到实际可选的方向并逐步推进”。AI 不能一律套在行业产品比较上；还需要分析目标、成本、时间、技能前提、外部机会和失败风险，在有限行动后重新评估方向；用户价值选择不能由 AI 静默取代。观察是否真扩大了可理解的选择范围，是否在不依赖 AI 时也提升了某些判断。

三例分别检验：**学习/安全、专业交付/研究、决策/发展**。若只测其中任一，会遗漏项目重要目标。它们是候选验证场景，暂未完成真实对照；已有源码研究可作非独立训练案例。

## 九、按真实价值重新选择工作，不等于再提出一套阶段制度

当前可马上使用的成果：GitHub 中已经有可信原始来源、部分真实源码控制测试、经验规则与典型失败；成熟执行平台也已经存在。因此应继续使用现有 GPT+GitHub 能力完成授权范围内的真实工作，复杂任务则按需比较整套成熟产品；不先重造记忆、调度或 Skill 架构。

第三块是**市场与成熟产品发现**：不限定 Hermes/OpenHuman/OpenWiki。按完整用户活动链寻找并检验成熟产品，只有确认现成品无法承载实际场景，才独立实现缺口。

**停止/重新打开研究的条件**：一次研究已提供能够改变当前选择的明确认识和可用交付，或者余下不确定项无法通过当前工具/授权解决时，停止该局部研究；但**不据此关闭上层长期探索**。遇到新的现实任务、相矛盾的证据、或重大产品变化时重新打开。

### 11.3 第一个完整问题示范：新手学习，不写成操作命令

**匿名化输入**：“刚接触激光切割设备，按钮都不认识，怎么开始？” 真实问题不仅是按钮，而是设备类型、能否获准操作、危险区域、原厂手册、现场师傅与安全培训。

依据 [HSE 工作设备培训](https://www.hse.gov.uk/work-equipment-machinery/training-competence.htm)、[设备防护与急停](https://www.hse.gov.uk/work-equipment-machinery/puwer-overview.htm)、[金属激光切割烟尘](https://www.hse.gov.uk/Welding/similar-to-welding-fume.htm)，输出一项**实际可用的新手观察任务**：

1. 让现场指导人员确认设备品牌/型号、说明书、学徒允许负责的事项。
2. 由专业人员示范识别急停、防护/联锁、危险区、烟尘抽排位置；不猜测按钮功能，不自己试运行。
3. 有板材移动或吊运时，先从固定、安全的观察站位建立可见参照，观察授权人员示范方向和停止，不独立操纵陌生设备。
4. 学徒应能够用自己的话说明“我负责什么、危险在哪里、哪些情况下必须停止并请教”，再进入机型特定培训。
5. 英国 HSE 用作**通用职业安全知识参照**，不代表英国法规自动适用于其他国家；现场规定、设备制造商和合格人员指导具有优先地位。

**产出**：已经形成可审查的新手学习提示和原始依据。**未发生真实机器操作、学习者技能测量或学后保留测试**。它说明不同任务有不同的有价值结果，不必先做一套专门的 Agent/Skill 系统。

在现有 GPT 与 GitHub 连接器能够完成目标的情况下，**不额外安装 Hermes、OpenHuman 或其他 Agent 也是合理的最小能力选择**。这不是任何第三方系统不合格的实测结论。

**实际交付边界**：只有本次 GitHub 文件更新及回读可称为真实交付。学习示范有来源但非实训；尚无跨模型 A/B，不能宣称这套知识系统因此提高了模型能力。

### 11.5 第三个方向：帮助人做现实选择，而不替人决定价值

对“我不知道未来学什么、做什么”这种短句，专业帮助不能自动改成“继续研究哪个 Agent”。至少要分清可立即借 AI 完成的工作、需要长期学会的技能、需要调查的现实机会、时间与成本条件、不可自动替用户确定的价值偏好。给出有实质差异的候选及适用条件，但不凭空承诺收益。这是**分析上的选择边界示范**，尚非真实个人职业决策的已验证改善。

- 未因连续说“继续”而安装 Agent、创建 Bot、开启后台监控、对外发布或修改 Meme 交易主体。
- 选择恢复此前被概括遗漏的“异质专业能力”和“现实价值/机会发现”方向，重新调查真正跨问题发现→专家方法→实际工作→长期修订的成熟系统，并把旧推荐降级为条件候选。
- 对既有仓库作最小范围审计更新、回读校验，不制造新系统提示词或固定阶段。

**为什么这不只是理论口号：** 源码/官方文档与原始研究来源可追溯；当前 GitHub 报告更新可核验；“是否因此令未来模型更聪明、普通人获得更多收入/能力”仍属未知。此轮仅展示**一次在已有权限下重新选择研究行动，并纠正项目历史记录**，不是独立的跨模型性能实验。

### 12.4 真正未被成熟产品整体解决的部分：把缺口限定为有证据的判断

1. **个人原始价值与多种可能目标的长期表示**：成熟记忆和 Goals 功能已有，但在真实复杂生活/工作任务中自动恢复、更改、调解长期价值偏好，尚无本项目可验证的完整方案。
2. **开放世界的专业未知与机会发现**：STORM 已具备主动追问和多角度探索的成熟方法，Meta 有专家认知修订，但“发现用户原先不知道、且现实上值得行动的新方向”仍需个案证据与外部反馈，不能因系统生成几个问题就宣称成功。
3. **将外部专家方法转化为适用的真实判断**：不是从专家知识仓库加载长提示词或增派角色；需检查情境、对象、限制和误用风险。已有相关理论，跨陌生领域稳定收益尚未在 ai-d 独立检验。
4. **从 AI 任务成功到人的长期实际价值**：完成一篇报告、一个程序或一次专业回答，不代表人的自主技能、经济机会或现实生活持续改善。现有相关实证是不同场景的间接来源。
5. **跨会话状态与可信进度报告**：2026 长程 Agent 研究提出真实弱点，尤其本项目对“只是保存到 GitHub”很容易给出过强的完成感；不能把消息中写了“执行成功”当作外部成果已经验收。
6. **研究何时充分及何时改变路线**：不是缺一套强制停止规则，而是缺真实目标与剩余未知的关系判断；已有框架只能作为帮助，不应无条件每次执行。

这些是**研究上的未充分解决问题**，并非声称全行业没有相关成熟产品或需要 ai-d 自建六个模块。

### 12.5 对当前项目的决定：停止以“下一组件”驱动研究，转为根据真实整件事自主选择

**应继续发挥的成熟能力**：在用户已使用的 GPT、GitHub、现成研究/执行产品中按需完成可授权任务；必要时引入 STORM 的多角度问题发现、Meta 的专家纠错方式、Work 的交付能力或 OpenHands 的代码执行。它们互为候选而不是必须安装的栈。

**当前可验证的“正确下一步”**：本节的历史修订、原始研究对照、否定上一轮惯性选型与 GitHub 审查回读。未来一条普通语言请求可以合理得出“继续研究”“立即执行”“转为教学”“选择替代方案”“询问只有人能决定的价值条件”中的不同结果；不应从“按照建议”机械推导固定动作。

**剩余证据边界**：未在本轮运行 STORM/Meta 内部代理/Work 云浏览器或 OpenHands 部署；未运行模型盲测，也没有现实收入、学习保留和长期跨会话效益实验。不以这些未测点否定已核实的机制，也不以 Github 文档更丰富来宣布 AI 综合能力系统已经建成。

**局部收束**：围绕“为何反复依照助手建议导致研究漂移”现已有足够证据形成阶段性判断：首要改进应是研究选择与原始目的之间的关系、实际交付进度核验，而不是再造强制流程。下轮若出现真实独立任务，应优先执行它，再从结果找重大认知缺口；不以本节为新长期强制路线。

## 十三、2026-11-07｜普通人如何借 AI 脱颖而出：从工具堆叠转向可持续差异与现实能力

> **性质：全局目标扩展与理论交叉研究，不是新总指令、不增 Agent/专家角色/工作流，也不宣称普遍成功或已验证盈利。**
>
> 用户此次提出的实际问题是：现有“专业知识、专家认知、跨学科思维、外挂大脑和工作流”只是想到的几个部分；在 AI 普及后，普通人真正脱颖而出还能来自哪些维度？哪些会被 AI 进一步商品化？需要重新从人、AI、市场与环境共同研究，而不是只扩充技术技能。

### 13.1 恢复八月未被充分带入 GitHub 的用户问题

根据可恢复的 2026-08-19 历史记录，用户明确追问过“当人人学 AI 时，普通人怎样利用自身条件形成长期可积累的优势”，并指出把优势归纳为“AI＋专业领域＋数据”仍过于原始。另一项原始思考是：人的身体状态、心理与动机、认知、价值、经历、周边环境和资源共同生成不同的想法与行动路径；AI 的帮助应适应这一差异，而不是所有人都配置同样的知识模板。用户同时重视长期谋生、现实价值与赚钱机会。**这是历史目标主题恢复，非逐字会话原文，也不是主张这些条件可以决定论式预测一个人的成功。**

由此纠偏：单纯把“专家知识/认知/工作流”从三项扩建成十几项，并不能回应“脱颖而出”；应该区分 **个人真实可用的能力、别人是否也易获得、市场是否需要、价值能否被本人获取、能否随时间积累**。这也不把人的生活目的降为收入单一指标。

### 13.3 完整优势空间：不是要求用户和 AI 同时建设八层

1. **人的现实条件与行动自由**：时间、精力、健康、经济缓冲、工作环境、教育基础、人际支持、法律及设备限制。先弄清哪一种帮助用户真正能用；AI 不能靠能力清单消除全部结构性障碍。
2. **自我方向与长期选择**：价值偏好、兴趣、经历、风险承受力、目标变化、自我管理。人决定为什么做，AI 可提供方案、发现错误假设与更好选择，但不能静默替换其生活目标。
3. **专业理解与判断**：问题表征、机制知识、专家方法、反证、跨领域联想；AI 可增强，也可能导致相似观点和错误迁移。优势来自找到他人遗漏的有用问题并正确处理证据，而非术语数量。
4. **真实需求和机会的识别或共同创造**：来源不只是互联网热点，还可能是现场反复出现但尚未解决的困难、非数字化的隐性需求、新顾客群与实际协作过程。AI 可帮助调查，发现不等于收入。
5. **行动、交付和可靠性**：能把想法化为质量稳定、可测量、有人真正使用的服务/作品/软件/学习结果；并处理责任、风险和出错修复。成熟 Agent、Skills、工具只是其中一些执行形式。
6. **信任、关系与价值获取**：即使人人都能产出相似内容，也未必都能得到客户、组织授权、真实分发渠道、推荐关系、可复验的声誉。价值创造与本人能留住多少价值不同。
7. **个人独有的复利资产**：领域实际经验、不断积累的案例和数据（必须合法取得/获得授权）、经过验证的流程、稳定用户/社群关系、可复用的产品或专业技能。资产会折旧，不保证永久稀缺。
8. **持续学习、适应与独立性**：不把 AI 的临时产出误认为自己已掌握；有反馈就修正、有失败就改变策略，必要时换模型和工具。能力不仅是变得更快，也包括知道什么时候不用 AI。

这些是**问题地图而非产品模块**。某个人的差异化可能只依靠其中两三项强结合（如现场经验+信任+AI 分析），没必要“全部修满”。

### 13.4 三种不同程度的优势：关键的新认识

**短期使用效率**：同样任务用了 AI 更快、更少错；有真实价值，但别人也容易学会。不要把它称为不可复制优势。

**情境性差异化**：独有经验、现实访问权、问题理解、受信任关系、学习和可靠交付与 AI 相结合，在某类具体需求中比通用方案更好。需要目标用户和业务证据，而不是 AI 自评“专业”。

**可积累的持续优势**：经过时间形成的可靠业绩、产品、客户关系、合法的数据/流程资产、能适应变化的团队与复利学习；能否真正构成持续护城河受市场、竞争、替代和资源控制影响，不能凭技术方案宣布获得。

**总判断**：AI 普及可能同时降低进入门槛与提高竞争强度；仅能更快产出不等于能捕获更多收入。普通人的目标应包括“扩大可选择的现实路径”而非唯一强调与他人竞争的排名。

### 13.5 对 ai-d 的非绑定研究方向修正

- **保留**原研究：普通表达、知识与专家认知、跨学科思考、开放未知发现、工作流、外挂大脑、Agent、长期记忆与知识修订，这些均为可用手段。
- **补回**三项常被忽略的要素：个人整体情境和资源转换；真实需求/机会是如何被发现或行动创造；价值交付之后怎样得到信任、分发、收入及可积累资产。不能因为旧知识没有这三项，就把旧研究判废。
- **警惕**四个失败：生成的大量“创业点子”没有用户需求；AI 让所有人产生相似的答案；成功案例是幸存者偏差；AI 替用户做完工作但本人未获得真实能力和价值控制权。
- **应用方法**：在出现具体真实任务时，按需要从学习、职业、专业项目、机会探索、产品销售/服务等方向选择有根据的最小成熟能力；先交付/验证再形成更深认识。**不预设 ai-d 必须开发新平台、固定八个 Bot、个人评分器或行为预测模型。**
- **证据边界**：本轮综合的是经典理论、2024–2026 的产品/劳动研究、创业理论与用户历史意图；没有独立的“AI 让普通人脱颖而出”长期随机试验，也没有证明用户具体收入、个人能力或商业竞争优势已经提升。下一步值得观察真实任务中的差异化结果，而不是继续补抽象层。

### 13.6 用户没有说“信息差”时，AI 是否应主动发现它？——纠正遗漏的实质案例

**这次纠正来自用户明确反例：** 面对“AI 时代普通人如何脱颖而出”的原始目标，上一轮 AI 虽提出专业知识、认知、执行、长期积累、信任，却没有充分自主提出“信息差、信息不对称和分散知识”所代表的经济机制。把它仅补入一份八项能力名单，会使今后又被另一个没提及的概念卡住。**重点不是“信息差”关键词入库，而是怎样从目标和现象发现未知相关学科。**

**无关键词示范（人工研究推演，非独立 A/B）：** 将原问题限定为“普通人怎样在 AI 普及后形成真实竞争优势”，不出现“信息差”。从“为什么结果不同”推到竞争中可获得的资源差异，再追问“谁知道什么、知识如何分散、寻找/核实信息的成本是多少、什么信息会改变决策”；最后才从原始来源引出 information economics、asymmetric information、dispersed knowledge、undiscovered public knowledge。与其同时存在的竞争解释有能力/资金/关系/制度/市场需求/执行质量等，不允许预设一定是信息差产生结果。

**不同机制不可混同：**

- [Hayek 1945, *The Use of Knowledge in Society*](https://contemporarythinkers.org/friedrich-hayek/essay/use-knowledge-society/)：知识分散于不同人及情境，任何一方难以拥有完整资料；适于解释真实世界的分布式知识，不等于分散知识本身带来盈利。
- [Stigler 1961, *The Economics of Information*](https://www.journals.uchicago.edu/doi/10.1086/258464)：搜索信息有成本，是否继续搜应考虑潜在收益；不能推出“资料越多越好”。
- [Akerlof 1970, *The Market for Lemons*](https://doi.org/10.2307/1879431)：交易中一方更清楚质量时可能出现逆向选择与市场失灵；**信息不对称不等于用户凭优势信息必然能够获利**，也可能是不知情者面临风险。
- [Swanson 1986, *Fish Oil, Raynaud’s Syndrome, and Undiscovered Public Knowledge*](https://pubmed.ncbi.nlm.nih.gov/3797213/) 与[后续科学文献发现综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC1459187/)：两块已公开却彼此孤立的知识可能通过机制桥接形成新的可检验假说；**公开连接发现 ≠ 假说已被真实实践证实**。
- [Design Council 的 Double Diamond](https://www.designcouncil.org.uk/resources/framework-for-innovation/) 主张先调查用户真正的问题，再重新定义挑战，而非直接完成用户最初想到的技术方案；[Stanford STORM/Co-STORM](https://github.com/stanford-oval/storm/blob/main/README.md) 提供视角引导的追问和从未使用证据生成新问题的实现入口，但不等于通用长程生活/经济机会 Agent。
- [March 1991, *Exploration and Exploitation in Organizational Learning*](https://doi.org/10.1287/orsc.2.1.71) 指出只利用既有确定性知识会压制长期探索；只不断开放搜索也会耗尽资源，二者须具体权衡。不能因此固定每轮全面枚举一套跨学科关键词。

**对完整项目的改变：** 项目研究主题不是“AI 技术研究”，而是用户面对的完整问题。AI 的专业强度应由“能否从普通语言主动发现会改变决策的重要未知机制”衡量；信息经济学只是这次证明原有概念视野狭窄的具体反例。职业问题可主动探索资质门槛、隐性招聘、岗位需求、通道信息和真实技能；软件研究可探索用户缺口、组织/信息流和价值回收；Solana Meme 研究可探索链上公开数据在解释与时序上的差异，但不得把未经证实的内幕、同控归因当作真实信息优势。

**应该避免的两种反向污染：** ① 此次漏掉信息差，于是永久要求所有问题先执行信息差检查；② 为防漏项而枚举经济学/管理学/心理学/技术所有领域，结果又陷入无边界形式主义。更恰当的做法是针对当前真正影响结果的未知因素，生成互相竞争的解释，按可能改变选择的价值去原始来源核实，适时交付。**这是一条研究判断，不写入全局强制提示词，也不称已经通过跨模型盲测。**
