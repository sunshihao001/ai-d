# ai-d 的四类实现路线：多视角方案比较与阶段性裁决

> **2026-11-07 修订**：本文件 2026-11-05 的 A/B/C/D 讨论的是“如何建设 ai-d”的不同**实现路线**，不是 ai-d 全部最终目的。用户新提出的上位方向是：建立面向普通人的、跨领域可迁移的 AI 时代综合认知、学习、谋生、行动与长期发展能力体系。愿景已记录在 [项目首页](../README.md)，以下保留原始阶段性裁决，避免历史目标被无声替换。

## 2026-11-07｜用户提出的上位愿景及其对旧路线的实际影响

### 新理解（上位目的；不等于已完成的产品）

- **真正的使用者**：可能不懂专业术语、缺少起步条件、需要应对职业和生活变化的普通人；也包括专业研究与项目开发人员。不能假设所有人具有相同资源、目标和家庭选择。
- **真正的成果**：人获得更多**可实际实现的选择和行动能力**，例如学会一种技能、完成一项实事、增加合乎条件的谋生选项、作出更可靠判断、适应职业变化，而不是把“知识更多、AI 回答更长、流程更复杂”当作收益。
- **所需专业跨度**：学习科学、认知/逻辑、经济与劳动、社会制度、技术与工程、健康安全、沟通协作及伦理。不同领域的应用必须使用相应原始证据，不能由某领域成功直接推广。
- **既有成果地位**：原 ai-d 认知内核、专家知识蒸馏、知识来源组织、跨项目 Skill/Blix 接入、工作流和“外挂大脑”，均是**在更高层目标下可保留的能力资产**。它们不自动成为唯一产品形式。
- **权限与价值边界**：个人重大生活选择由人决定；AI 负责发现选项、研究与执行有权限的事项；医疗、金融、法律、私人资料等场景仍受各自专业与安全边界限制。

### 由此修正旧 A–D 路线定位

| 2026-11-05 的路线 | 修订后的角色 | 不能由该阶段声称的能力 |
|---|---|---|
| A 专业知识参考库 | 通用专业来源、经典思想和可迁移经验的储存/导航基础 | 知识已自动内化、普通人已获得就业/生活成果 |
| B 知识适用与实际效用检验 | **当前依然应优先做**：把成熟知识连接到真实人生或业务任务，辨别何时有效 | 自行设计案例和给自己打分就能证明公共价值 |
| C 可移植 Skill／跨项目接口 | 让 Meme、制造业等异质场景共享认知方法并保留本地专业事实 | 提供一个 Skill 文件就等于所有模型自动继承能力 |
| D Agent 平台/完整软件 | 当真实用户任务证明需要连续状态、权限、工具与反馈时可能成为交付载体 | 远期愿景成立就必须先建大型社会化操作系统 |

**当前策略并未发生“所有功能同步开工”的改变**：目标上限扩大，执行上仍从真实任务和已具备的成熟资产出发；优先在差异显著的两个领域建立完整证据链（例如专业市场研究工具开发与非软件职业学习支持），先看能否产生可交付成果、减少知识门槛、保留人的判断，再考虑对外产品化。两个领域仅是早期验证样例，不代表“人的全部需要”已覆盖。

### 需要被严肃反证的竞争力假设

**假设**：低专业门槛、跨学科解释深度、从认知到交付的闭环、跨模型知识更新与可追溯失败经验结合，可能区别于只提供单次聊天、工具封装、课程或文档检索的产品。

**反证**：用户无法从入口真正理解问题；错误建议/幻觉或过期知识增加；用户把决定权让给 AI；跨行业迁移失败；成本/隐私风险超过收益；与已有成熟产品相比没有任何实际增益。若出现这些，应直接缩小或改变实现方式，而不是扩建专家与架构。

**对外声明边界**：当前没有独立用户样本、持续结果或市场竞争对照；“在行业脱颖而出”是用户追求的长期方向，不是事实结论或产品能力承诺。可采用[联合国人类发展报告2025](https://hdr.undp.org/content/human-development-report-2025)、[能力方法](https://plato.stanford.edu/entries/capability-approach/)、[OECD Skills in AI Age 2026](https://www.oecd.org/en/publications/skills-in-the-ai-age_972bd15e-en/full-report/component-4.html)和[NIST AI RMF](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-ai-rmf-10)作为外部研究入口，但具体效果仍需独立验证。

## A｜知识参考库
**目标**：保存人机协调、目标推理、专业认知、Agent 实践、原始论文、反例。
**优势**：简单、易审阅、跨模型、公开资料引用方便。
**失败方式**：只会越积越多，无法解释何时用、如何改变行动；用户此前已出现过此类负担。
**适用条件**：研究与知识来源尚不完整，需先保证资料可追溯。
**裁决**：基础功能必须有，但不是最终价值定义。

## B｜通用认知方法的适用与评测中心（首选）
**目标**：从 A 中选择有证据的方法，测试不同任务如何调用、何时失效、什么新知识真正改变决策。
**优势**：从“保存内容”走向“在真实任务里有用”，最符合旧知识保留但避免过度约束的要求；可接不同模型。
**失败方式**：自评偏差、只挑熟悉案例、额外检索成本大于收益。
**成立条件**：至少两个异质任务、原始任务一致、检索资料可比、参考事实可查、输出判断有可核查变化。
**裁决**：**当前优先路线：A 作为材料基础，B 作为专业能力建设的主线**。

## C｜可插拔 Skill / MCP 知识适配层
**目标**：使未来 Grok / GPT / IDE Agent 或其他工作流按需使用经验证方法。
**优势**：交付接口清楚；可将专业能力嵌入现有运行时。
**失败方式**：提示词封装导致跨任务过拟合、接口维护、错误知识被强制加载。
**成立条件**：B 证明具体知识确有迁移增益，且至少两个消费者有明确的相同调用需求。
**裁决**：保留为条件性路线，不预先建一堆 Skill。

## D｜人机协调操作系统 / 自主 Agent 平台
**目标**：用统一产品运行意图理解、记忆、规划、工具、调度、权限、评价、目标更新。
**优势**：可承载长期无人值守任务和完整 UI。
**失败方式**：重造 OpenAI Agents SDK/LangGraph/MCP/A2A 已成熟的组件，增长复杂度压制研究质量；潜在目标漂移和授权失效。
**成立条件**：现有 GPT + GitHub + 成熟 SDK 无法满足被验证的实际长任务需求；预计收益明显大于搭建与维护成本。
**裁决**：暂不作为当前开发目标；真正出现缺口时应先复用成熟 runtime。

## 五种视角重新评判
| 视角 | 最优先的事 | 反例或风险 |
|---|---|---|
| 人的长期目的 | 允许目标演化，人保留重大决定 | AI 自己不断扩大目标导致偏离 |
| 专业研究者 | 从原始证据生成有条件、可反证的新认识 | 只增加概念与引用，未改变结论 |
| 产品负责人 | 找到可检查的交付与用户收益 | 构建没有用户验证的“总架构” |
| 工程负责人 | 用成熟协议与 SDK 解决执行基础设施 | 重造状态和工具层 |
| 质量评测者 | 比较基础模型与选择性知识调用 | 同一 AI 自评、过拟合和假对照 |

## 何时推翻当前建议
- B 在独立任务中稳定增加错误、成本、用户负担，且无可靠增益：退回 A 并修订知识触发条件。
- C 的两个真实工作流需要共用相同规范且有明显维护收益：优先做有限 Skill/MCP 适配。
- D 所需长时状态、审批和持续执行能力无法通过成熟框架满足，且已有实际业务收益证据：再评估独立平台。

**当前决议**：研究型通用内核，不等于统一软件中枢；主攻“目标变化＋证据适用＋下一动作价值＋可验证迁移”，保留未来基于用户选择改变方向的权力。
