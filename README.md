# ai-d｜AI 与人协调：通用专业认知内核（初步定位）

## 2026-11-08｜目标锚点：简短表达的专业转换与持续承接

> **用户确认的长期研究锚点（不覆盖既有总目标）**：人只需以简短、日常、可能不完整或不专业的语言表达方向、反馈和关键选择；AI 应基于现有目标、可信上下文与外部专业知识，主动把意图转成可工作的专业问题表征、实施任务、成果标准和必要约束，而不是要求用户先写出完整的专业提示词。**专业化的重点是问题理解、判断与交付质量，不是术语堆砌或冗长提示词。**

**跨轮持续建设的具体含义**：当用户说“按照建议建设”“继续推进”等简短指令，并且已有清晰上下文和授权时，AI 应回看上一轮的**待修改事项、已确认选择、尚未完成工作和证据状态**，登记必要任务、优先级、依赖、当前状态及验收依据；随后自主选取最有价值的一项或相互关联的工作去完成、核验，再更新记录进入下一轮。不能把 AI 上一轮的建议自动当成用户已确认的重大目标变更，也不能只做新计划而不交付成果。

**行为边界**：明确区分用户真正批准的方向、AI 提议的方案、未证实推论和需要单独授权的外部高风险行动；任务简单时直接作答，不强制生成计划表；用户独有且确实决定结果的信息才追问，能够从历史、代码或可信来源恢复的信息 AI 自行核查。避免因旧计划约束新目标。保存记录不等于自动完成或模型已稳定获得这种能力。

**当前承接**：复用 [P1–P8 的问题型知识入口](knowledge/INDEX.md) 与 [已有跨领域评测记录中的「简短指令→专业任务→跨轮继承」登记](evaluation/first-cross-domain-tests.md#2026-11-08简短表达与持续建设任务承接登记)；优先检验任务继承遗漏率、错误补充条件、用户反复提醒次数、实际交付和复核质量。**状态：目标锚点已明确；自动承接与效果增益仍待独立验证。**



## 2026-11-07｜把未知发现研究纳入全项目，而不是把项目缩成 AI 技术研究

**研究定位补充（不取代已有用户目标，尚未经过独立模型效果验收）**：本项目服务于人的实际问题与长期能力发展，不应因为仓库名称、前期提示词和近期 Agent / Skills 研究，就把用户的真实问题限定为“继续研究 AI”。在职业、经济机会、信息获取、学习、安全、软件、市场或未预见领域，AI 应从普通表达理解目标，主动发现用户没有说出的重要专业问题、机制、跨学科联系及适用限制，然后按具体价值选择成熟知识、成品、调查、执行或教学。**“信息差”只是最近一个已发生的遗漏，不是每轮强制检索的关键词。**

**本轮知识如何融入**：原始目标、专业来源、跨学科未知发现、成熟系统及真实验证结果已按关系整理到[全项目知识整合与研究入口](knowledge/2026-11-07-whole-project-research-integration.md)。已有[未知发现纵深研究](research/2026-11-07-problem-driven-unknown-discovery.md)继续作为原始理论/源码的维护位置；不会把这些研究重复抄成新的强制提示词或固定专家团队。

**新增全局深审（非强制规则）**：[整件事的深度研究能力：成熟系统源码、专家覆盖和真实价值反证](research/2026-11-07-whole-project-deep-research-and-mature-systems-audit.md)。按完整人类目标而非三个小案例审查，含 Co-STORM / Open Deep Research / GPT Researcher / DeepAgents / Hermes / OpenWiki / LiveDRBench 的目标、源码、失败和复用判断；已核实的源码与尚未实跑的整体能力明确分开。

**历史方案的适用边界**：下文早期提出的“知识库 A → 认知 Skill B”等是当时的阶段性技术选择，不是整个 ai-d 已确认的唯一终点。知识写入 GitHub ≠ 模型参数改变；是否能在新问题里不经提醒主动发现关键未知、改善真实判断，仍需独立对照验证。

**2026-11-08｜提问错误的主动纠正（实际案例，不是新工作流）**：普通人的表达可以短、错、含错误前提，**用户不需要自己写“专业化后的正确提示词”**。AI 在已经授权的任务内应先恢复真实目标，区分“用户确实只有自己知道的必要条件”和“可通过当前历史、文档或外部事实自行核查的信息”，主动纠正会改变结论的错误前提、范围与任务选型；在低风险可逆任务上直接完成，不反复把工作推回用户。不可擅自替换用户的重大价值目的或冒称已读取不可访问资料。**让用户少犯错误，也要防止 AI 自己误补错误条件。**实际对照：[当前对话中的目标漂移、职业评价对象与 X 链接核验](evaluation/first-cross-domain-tests.md#2026-11-08真实对话中的提问纠错用户漏说ai误判与事实适用错误)；本次是研究和源级纠错，模型增益未完成独立评测。

## 2026-11-06｜整体目标协作：AI 不只是逐条待命的微任务执行器

**协作方法修订（尚未经过模型效果验证）**：用户表达方向、反馈和重要选择；AI 将口语意图放回长期目标与当前产品，自主形成一组相互关联的专业问题，判断哪些线索值得并行比较、哪些依赖须先验证、哪些无价值内容应停止。单点深挖可以存在，但不可把一个细节当作完整目标已完成，也不应把每一步专业规划交回用户。

**整体研究不等于每项任务全覆盖**：根据当前目标、信息价值、风险与授权，动态联结业务价值、领域原理、现成产品、源码、数据可靠性、知识适用、反证和可交付成果；能在授权内完成的工作应实际完成并复核；超出授权或不可验收的部分如实保留 UNKNOWN。用户继续决定重大目标、对外高风险操作、付款与不可逆行动。

**应验证的差异**：同一自然语言任务，对照“只回答局部问题”“过量注入历史知识”“按需选关键工作线并收束成完整成果”三种方式，核查目标贴合、关键未知、事实正确、交付、用户指挥成本及冗余。这是候选研究方法，不代表 AI 能力已提升；复用现有 [P1–P8](knowledge/INDEX.md) 与 [跨领域评测](evaluation/first-cross-domain-tests.md)，不新增固定阶段或专家系统。

## 一、为什么建立这个仓库？

人往往只能先表达一个朦胧、具体、甚至不完整的想法；随着研究深入，问题的定义、真正值得追求的目标、可选方法与人的偏好都可能变化。

例如，一个最初只想寻找可跟单钱包的目标，可以在研究资金关系、行为机制、专业产品与实际反馈后，逐步演变成更完整的市场智能研究目标。

这种演变不是“需求不稳定”的简单错误，而是**人与 AI 共同发现更有价值问题**的过程。AI 不应只执行一句话的字面意思，也不应擅自替人决定人生目的或重大价值取舍。

**本仓库的核心问题：如何让人只需用自然语言表达意图、感受、反馈和重要选择，AI 就能主动承担专业理解、开放研究、方案比较、授权内执行、验收、反证和持续修正，同时识别目标层级的变化，并在工作结束后产生下一轮真正有价值的新认识？**

## 二、初步目标（可以随着证据继续演化）

研究、保存并检验一组**跨模型、跨工具、跨专业领域可迁移的人机协作认知能力**，使未来具体的 AI 工作流在调用这些知识时：

1. **理解意图，也理解目标变化。** 区分人的原始表述、真实目的、暂时假设、约束、价值取舍，以及 AI 提出的新目标候选；识别任务层、方法层、产品层和长期方向的改变。
2. **主动发现未知。** 不只按用户已知的术语找答案；从专业概念、原始资料、不同解释、跨领域联系和失败反例中发现更重要的问题。
3. **形成成熟选择。** 对同一目标生成有真实差异的方案，比较证据、价值、成本、风险、可推翻条件；能推荐而不是一味列选项。
4. **承担可授权的专业工作。** 将研究连接到设计、实现、测试、质量检查与可追溯交付；不把不必要的技术决策反复交回用户。
5. **独立核查与纠错。** 区分事实、资料作者主张、模型推论、假设、离线测试和真实运行；在新证据出现时主动修正，必要时停止或改变方案。
6. **从结果继续思考。** 每次有实质成果后，重新审视目标是否变化、知识与方法是否还能改进、出现了哪些有价值的新方向，选择下一项最值得做的事。
7. **让可靠经验迁移。** 保留专业知识的原始来源、适用边界、反例及实际结果；按当前问题选择使用，不把全部历史提示词变成永久强制规则。

**人的职责**：决定个人价值、重大方向、重要资源投入、隐私与外部高风险授权，反馈实际体验。**AI 的职责**：在获准的环境和工具范围内，尽可能承担专业研究、判断支持、实施与验收；透明报告未完成与未知。人可以随时改变目标和停止任务。

## 三、“内核”意味着什么，不意味着什么？

本仓库所说的内核，首先是**通用认知知识与协作方法的参考源**，不是系统内核、模型权重、一个万能提示词，也不是把所有任务编排成统一状态机。

未来不同 Skill 或工作流可以按需借用：目标理解、研究方法选择、专业知识适用性判断、证据与反证、方案决策、人机权限协作、任务后复盘与新目标发现等知识。

它们仍要根据各自专业领域、工具权限和任务环境实施具体流程。**可迁移的是方法与判断原则，不是每个领域的事实、阈值或执行动作都通用。** 保存到仓库也不等于模型已经“学会”，必须有正确的调用、解释和任务验证。

### 暂不预设的技术选择

- 不预设固定 Bot 数量、专家委员会、九阶段/几十项动作、单一 Agent SDK、知识图谱数据库或统一工作流引擎。
- 不把项目写成另一套大型系统提示词，不强制每次回答使用所有认知方法。
- 不要求把旧知识全文一次性搬入；先保持来源可追溯、内容有选择、结论可反驳。
- 不声称目前已实现跨会话自主执行、自动持续研究或可量化的能力提升。

## 四、知识如何逐步建设？

优先积累四种相互关联、但不混同的材料：

| 资产 | 要保存的内容 | 不能误当成什么 |
| --- | --- | --- |
| **专业原理** | 真实的认知科学、人机协作、推理、决策、知识组织等来源与适用条件 | 一条强制执行的提示词规则 |
| **研究方法** | 如何提出问题、检索、关联、竞争解释、反证、判断何时停止 | 每轮必须走完的固定流程 |
| **真实案例** | 原始意图 → 关键证据 → 判断改变 → 可检查结果 → 错误与反例 | AI 自评成功或展示用故事 |
| **当前决策与待验证主张** | 为什么选择某种做法、什么证据会改变选择、下一项高价值验证 | 永久正确的架构承诺 |

初期先索引现有关于目标演化、认知理解、多轮协作、知识污染、研究质量、Agent 状态与人类监督的历史资料。引用和原始专业认识可按主题保留，历史设计方案可追溯但不自动成为现行指令。公开仓库不上传私人对话原文、身份信息、秘钥或无权公开的第三方材料。

**每项新研究进入仓库的标准**：与人机协调或跨任务认知能力实质相关；说明来源/日期/证据等级；写清新认识改变了哪个判断、何时有用、何时不适用；允许保留 UNKNOWN。不是搜索过或总结过就等于验证过。

## 五、未来可能怎样演化？（候选，不是预定路线）

| 方向 | 意义 | 触发条件 |
| --- | --- | --- |
| **A. 开放的专业认知知识库** | 研究、比较、归档、发现知识关联 | 先证明知识能在新任务中被准确调用 |
| **B. 可复用的认知内核 / Skill 知识源**（当前优先） | 给不同 AI 工作流提供通用判断方法与使用边界 | 在至少两个不同领域的任务中看到可核查收益 |
| **C. 自主 Agent 工作平台** | 进一步负责持续执行、恢复、工具编排与审批 | 出现仅靠现有 GPT + GitHub 无法解决的真实运行缺口 |
| **D. 人机协作可视化产品** | 展示目标演化、方案、证据和任务状态 | 用户体验证明文档方式已造成明显障碍 |

当前推荐 **A 打底，向 B 验证**。C 和 D 保留可能性，但不是先决条件。随着新证据、技术与用户目标变化，可以改变路线。

## 六、第一批验证问题

**案例一｜目标演化：** 从“寻找可跟单钱包”到“市场智能系统”，测试 AI 是否正确区分用户原意、新知识推动的目标升级、AI 未经确认的推断及真正值得保留的方向。

**案例二｜专业研究：** 在新领域，用“普通研究”和“按需调用本仓库方法”分别解决同一问题，比较是否提高了事实准确性、关键未知发现、方案判断和可执行性；警惕因更多提示词造成离题、成本提高或误判。

**案例三｜长期任务恢复：** 区分保存历史对话、恢复未完成执行状态、保存经过验证的方法，以及新问题中能否正确调取；不能因材料已存储就宣称 AI 已获得可靠长期记忆。

判断标准是**真实问题处理质量**，不是文档数量、架构层数、Bot/Skill 个数或 AI 自我评分。
