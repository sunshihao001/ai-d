# 04｜Source Policy

## Source roles

### X
Best for:
- emerging ideas;
- current practice;
- experiments;
- failures;
- practitioner discussion.

Weakness:
- high noise;
- self-promotion;
- incomplete context.

### GitHub
Best for:
- implementation;
- architecture;
- code;
- tests;
- issues;
- PRs;
- releases;
- real project history.

Weakness:
- a repository can be abandoned, incomplete or overclaimed.

### Reddit
Best for:
- user experience;
- failures;
- objections;
- workarounds;
- community disagreement.

Weakness:
- anecdotal and uneven expertise.

### Official docs
Best for:
- intended behavior;
- APIs;
- constraints;
- authoritative definitions.

### Papers / books
Best for:
- principles;
- formal methods;
- research findings;
- deeper conceptual understanding.

## Source rule

A source is evidence for a claim, not automatically a conclusion.

The system should preserve:
- source identity;
- date/version when relevant;
- exact claim or observation;
- source role;
- limitations.
