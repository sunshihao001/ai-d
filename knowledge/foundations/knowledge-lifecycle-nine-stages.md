# 知识九阶段：从原始知识到判断、行动和修正（V1.0）

日期：2026-11-13。性质：用户确认的通用认知锚点，适用于 AI 协作、科研、软件建设、行业调查和真实问题解决；不是新程序架构、九个固定 Agent、九张每轮必填表，也不是模型已经掌握这些能力的实证证明。

**核心概括：规划 → 获取 → 接收 → 理解 → 关联 → 整合 → 转化 → 验证 → 进化。**

**核心目的：** 用户只用简单自然语言表达目标，AI 负责根据任务主动发现知识需求与隐含缺口、寻找成熟知识、理解并连接原理、选择实际用法、授权内实施并核查结果，持续修订错误，让知识真正改变问题表征、决策与可交付成果。重大目标、资金和外部不可逆操作仍由人决定。

## 1. 三个互不替代的维度

- **纵向九阶段 K1–K9**：一项知识在形成、联系、应用与修订过程中，究竟经历了哪些认知工作；允许跳跃、并行和反馈，不要求每个问题走九次。
- **横向问题与专业领域**：沿用 ai-d 的 P1–P8 问题索引；专业数据仍留在 Blix（Solana经济调查）、Claude（具体产品操作）、激光切割（岗位操作）等各自领域。跨学科联系保留引用，不能把专业事实全部搬来 ai-d。
- **证据状态**：作者明确宣称、可观察源码/真实原文、理论互证、竞争假说、离线测试、真实运行、独立效果对照、未知分别描述；证据等级属于具体主张或场景，不能给整篇文章盖一枚“已验证”。

九阶段属于知识的**生命周期视角**，P1–P8属于**问题导航视角**，各项目六环/业务交付属于**目标视角**，三者绝不相互替代。来源 SOURCE、概念 CONCEPT、方法 METHOD、案例 CASE、主张 CLAIM、决策 DECISION 等对象类型继续沿用现有维护规范。

## 2. 九阶段的关键前置、实际成果与漏项预警

| 阶段 | 必须提前想到的关键环节 | 最小有意义产物 | 失败与未知预警 |
|---|---|---|---|
| **K1 规划** | 从用户意图、已确认目标、既有成果和权限重建问题；找专业领域、隐含条件、依赖、成功/失败定义、成本与关键未知；比较有实质差异的起点 | 可修订的知识需求、范围、价值与开放问题 | 将 AI 提案误当用户目标；只按字面实施；上游数据/技术条件根本未具备 |
| **K2 获取** | 按问题使用行业术语、俗称与多语言组合；优先查看 GitHub 成熟完整项目、X/Reddit原帖与评论、YouTube实操、原始论文、经典书、官方规范和实际反例；选择合适来源覆盖 | 来源与检索范围、版本、未覆盖点、下一项高价值资料 | 搜到了README就算吃透；只找证明自己对的材料；无限搜索却没有增量 |
| **K3 接收** | 保存必要原始源码、测试、文档、历史版本、讨论、原始交易或研究记录；分清原文、二次摘要、作者主张和模型推论，标注许可及未审阅部分 | 可回查原始来源和证据边界 | 过度压缩致失真；未存关键原文；重复引用误当多份独立证据 |
| **K4 理解** | 还原原系统自身问题、作者设计意图、内部机制、条件、缺陷及替代；概念与实际运行行为分开；未能证实作者动机时标推测 | 可解释的机制模型、适用前提与失败条件 | 罗列功能当理解；只按自己业务需要摘代码；未理解完整工程链 |
| **K5 关联与反证** | 比较跨项目/学科的相同机制、差异条件、冲突和竞争解释；识别关联背后的来源共用与伪互证；产生可被新事实推翻的假说 | 知识关系、反例、新问题、可检验预测 | 用术语类比冒充机制成立；理论互证冒充实证；研究永不收束 |
| **K6 整合** | 按真实问题、学科、对象类型、来源与证据/适用性多维组织；去重、建立上下位/支持/反证/来源/用途/修订关系，保留未知和一处主要维护版本 | 按需可调用的知识入口与证据关系，不要求每条新建文件 | 知识目录无限扩张、重复建专家/层级；旧上下文污染新目标 |
| **K7 转化与决策** | 判断知识能否改变问题表征、选项、规则、实操参数、教学、可运行工具或产品；比较整套复用/有限修改/组合/另建/仅保留理论，先查授权、成本、依赖 | 明确改变了哪个解释、选择、行动及其边界；可执行但未运行时标候选 | 归档当落地；纯理论被强制编码；未经授权交易/支出 |
| **K8 验证** | 对关键主张选择合适证据：原始事实、独立反证、可重复离线实验、真实对象运行、样本外对照；保留失败、缺口与效果边界 | 可复查的测试结果、成功/失败和未验证事项、相对旧方法的增益与成本 | 合成案例当真实链；同一个AI自评当独立验证；涨幅当交易收益 |
| **K9 进化** | 将真实反馈回写原有知识、问题定义、资料来源、适用条件、技术选择；记录为什么修订、何时不再引用旧规则、下次复查条件和研究停止理由 | 原位版本化、错误更正与下一项高价值未知；实际结果推动下一轮选择 | 每次纠偏变新强制流程；文档多而运行/判断不变；反复从零规划 |

三个认知层次：**形成（K1–K4）、发展（K5–K7）、应用与进化（K8–K9）**。这是总结关系，不是额外三套软件。

## 3. 重要反馈路径

- K5发现证据冲突，返回K2/K3核原始来源；如果需要，返回K1修改问题定义。
- K8发现失败，返回K4检查机制理解、K7修改使用方案；不是立刻升级整个架构。
- K9发现旧知识过时，原位修订K6的主要维护条目，保留旧版本和失效条件。
- 真实任务在某一环节已足够，就允许停止。小问题无需预先执行九阶段；复杂任务可在K1先检查大类覆盖后，从最有信息价值的缺口开始。

## 4. 预先发现遗漏：只在复杂/高成本任务使用的知识雷达

必须能够识别这些风险类别：
1. 目标与授权是否明确，用户确认的目的和AI自己的建议有无混淆？
2. 来源是否可靠、足够完整，哪些对象从未进入数据采样、来源覆盖或筛选？
3. 原始事实、作者解释、代码可观察行为与模型假设是否区分？
4. 是否存在不同领域的关键机制、竞争解释、反例和反直觉证据？
5. 新知识需要改变什么实际判断/方案/行动？有哪些现成成品可优先复用？
6. 成本、许可、部署、依赖、安全与结果的验收条件是否足以执行？
7. 哪些问题目前无资料、只有假设或需要真实使用才能判定？何时重新检查？

有实质影响的未答事项按 KNOWN / PARTIAL / UNKNOWN / UNVERIFIED / BLOCKED 标记，说明验证入口，不要求用户逐项填表，也不因未知可能无限存在而永不实施。

## 5. 与已有知识体系的具体对齐

- 继续使用知识总索引 P1–P8 作为**专业问题入口**，不另建九套知识分类。生命周期K1–K9用于发现研究流程的断点。
- 继续使用现有知识维护规范的 SOURCE/CLAIM/METHOD/CASE/DECISION 类型、来源、去重、关系、版本、适用与失败条件；九阶段不是新数据库模式。
- 继续使用 ai-d 的“普通表达→目标理解/发展/选择”和“低价值研究风险锚点”，但都不转成强制阶段。
- 继续使用 ACTIVE-RESEARCH-LEDGER 承接重大未完成问题，不逐条记录每个琐碎知识卡。
- Blix六大业务目标（市场机会、关键钱包、资金库存、跨Mint、可参与性、监控）不能被九阶段替代：九阶段用于帮助**建设与验证**业务能力，而不是业务本身。

## 6. 项目应用实例：Blix的“关键钱包/跨Mint资金调查”

K1先识别完整业务目标及数据采集前置；K2/K3读取原版Blix、成熟开源索引器及Solana交易结构和实际签名；K4分清TokenAccount、Owner、FeePayer、CPI、交易对价和库存；K5对“共同控制/共享设施/普通交易”提出不同解释；K6把来源、角色、原始签名和可复查反例归位；K7转化为只读调查工具或判断原则；K8在真实Mint和签名中验证并与原版做对照；K9因失败/新事件修订解释和调查路线。

如果没有历史原始签名，现状是 SOURCE_GAP / UNKNOWN，不是“没有卖出”或“没有关联”；如果没有可执行进出报价，不能把资金行为推成实际跟单盈利。

**与工程跨层锚点的连接：** [项目多层锚点与跨层一致性](cross-layer-project-anchors.md)说明K4/K5形成的专业事实如何约束K7的设计与代码，K8的测试怎样验证，K9的变更如何反向修订知识与项目。它不是九阶段的新环节，知识的原始主张与代码实现必须各保留证据边界。

## 7. 生效范围、待验证效果与停止点

**已确认的只是认知规划方式，不是模型性能提升。** 本文件保存后并不会自动进入每一轮模型上下文，不代表完成自动检索、自动实验或真实业务闭环。真正评价九阶段有用，应对比在同一新任务、同等事实和预算下，“直接按字面实施”与“提前补全知识/前置条件并按需执行”的结果，观察重要遗漏、错误前提、真实交付、用户纠正成本和额外耗时。

如继续添加阶段、概念或文件已不能改变真实解释、可执行选择、验证效果，停止扩展该知识路线。保留理论知识的独立价值，避免以立即变成功能为唯一标准。

**稳定锚点**：知识必须帮助用户及AI更准确地理解问题、发现专业未知、形成有依据的选择，并将其转化为可核查价值，在新证据中修正；不能让知识整理本身成为新的项目终点。
