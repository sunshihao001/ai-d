# 知识分类、来源、更新与去噪｜轻量维护规范 V0.2

日期：2026-11-06｜适用对象：ai-d 的公开专业研究资料。**不是系统提示词，不要求每个问题都走完这些动作。**

## 1. 四个彼此独立的分类维度
1. **问题归属**：参照 [知识总入口](../INDEX.md) 的 P1–P8，选一个主要问题，必要时再加相关问题；不要只按学科建孤立文件夹。
2. **学科来源**：管理学、组织学习、图书情报学、认知科学、决策科学、运筹学、哲学、科学研究、软件工程及未来任何合适领域；是可多选的标签，不是封闭行业目录。
3. **知识对象**：原始来源、概念、主张、方法、案例、假设、决策、评测或授权边界；其中事实主张与方法不同、历史决定与用户当前目标不同。
4. **证据和适用性**：原始来源是否核对，具体主张是否受支持，是否能迁移到当前问题；有无冲突/新证据/失效条件。不能用单一数值代表所有可靠性。

## 2. 一个知识对象的最低信息（优先自然 Markdown）
| 属性 | 必需性 | 说明 |
|---|---|---|
| 名称和稳定链接 | 必需 | 一个核心概念或主张只有一个主要维护位置 |
| 主要问题与相关问题 | 必需 | 例如 P3 检索、关联 P6 决策 |
| 学科来源与知识类型 | 必需 | 如“组织学习论文 / 方法假说” |
| 核心认识及支持它的具体来源 | 必需 | 出版方、原始论文、官方标准、真实案例；来源必须与主张相配 |
| 适用条件与不能证明的部分 | 必需 | 哪些场景可以借鉴、何时不适用 |
| 实际判断变化 | 有实例时填 | 没有真实任务结果就写“尚未验证增益”，不要伪造 |
| 修订/冲突记录 | 出现更新时填 | 新证据、旧观点、变更原因和时间 |

**不要求为这些属性创建数据库或 JSON 卡片。** 少量有证据的 Markdown 段落＋清晰链接即可。只有任务确实需要自动查询或批量管理时，才考虑结构化导出。

## 3. 保留多种不同关系
- **broader/narrower**：术语的上位和下位；与 **related**（概念关联）区分。
- **supports / contradicts**：某项证据支持或挑战某个**具体主张**，而不是支持整个文档。
- **applies_to / fails_when**：明确使用场景及失效边界。
- **derived_from**：说明知识如何从原始来源或前一版本形成。
- **supersedes**：新版本替代旧判断，旧材料留存但不再默认使用。
- **changes_decision / tested_by**：具体知识如何影响选择、由哪个可复核任务检验。

基于 W3C [SKOS](https://www.w3.org/TR/skos-primer/) 的概念关系、[PROV-O](https://www.w3.org/TR/prov-o/) 的溯源思想，以及 [Dublin Core](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/) 的元数据原则；这里只借鉴必要思想，不宣称实施了 RDF 或完整本体。

## 3A. 避免“应用对象先行”造成研究视野收缩

**跨领域方法修订（2026-11-06，来自Solana Meme/Blix参考项目审查，效果待验证）**：一个外部项目不只是当前目标的零件箱。若先问“它能补我什么功能”，就可能遗漏原项目自主定义的研究问题、设计取舍、测量语义、失败经验和可迁移的未知机制。资料研究应先独立还原来源自身的知识版图（文档、代码、测试、演化与竞争解释），然后才做面向应用的选择、去重与集成裁决。没有当下应用位置的有价值主张保留来源和开放问题，不能自动丢弃；复制到产品仍需证据、许可和真实能力验收。

**深度与负担的平衡**：保留全目录覆盖清单及未审阅状态；依信息价值逐主题深读，不要求对每行代码创建卡片，也不默认把项目全文注入模型。至少区分目录已扫描、内容已读、主张证据已核对、跨来源冲突已检查、实际使用已验证。新认知可提出修改应用产品路线的候选，但未经用户确认不改其重大目标。此原则属于 P2/P3/P4/P5/P7/P8 的交叉研究方法，不新增强制流程层。

## 4. 知识何时加入、修订或停用？
- **新内容**：与现有主题不重复，有新来源、真实反例或能改变某项判断；否则先补原文件，不另建同义卡片。
- **来源冲突**：保留竞争主张、适用条件和差异证据；暂不强行得出统一结论。
- **旧规则失效**：保留历史背景和修订理由，停止自动当作当前指令。
- **需要新方向**：提出“值得研究的假设”，与用户已经确定的长期目标分开。
- **无实际增益**：保留为背景知识，但不进入默认工作上下文。
- **局部研究停止或暂停**：如果下一项检索不能说明将改变哪个关键解释、竞争假设、验证证据或可行动决定，停止扩展该分支；若关键证据不可得，标记 UNKNOWN 并登记复开条件。新来源能改变判断时可重新开启，不能用“研究永不结束”要求每轮无限增加资料。详细理由和来源见 [问题驱动研究第九节](../../research/2026-11-07-problem-driven-unknown-discovery.md)。
- **资料过时**：记录最后核对时点、适用环境、需要更新的来源；不能仅根据发布日期就否定经典理论。

## 5. 噪音与污染的六种不同来源
| 问题 | 要检查什么 | 应怎样处理 |
|---|---|---|
| 资料噪音 | 搜索结果只是营销、重复转述或不相关 | 优先一手来源；有价值再继续搜索 |
| 概念噪音 | 同一意思被多个命名和缩写重复建档 | 标准术语+别名；合并或交叉引用 |
| 证据污染 | README、作者自述、推论、离线测试和实跑被混级 | 对每项主张单独标记证据 |
| 上下文污染 | 与当前任务无关的旧设计、提示词被全部注入 | 按问题加载最少相关资料；允许忽略旧规则 |
| 目标污染 | AI 提出的候选被记为用户已批准的方向 | 目标来源、确认状态、权限分开保存 |
| 评测污染 | 同一模型出题答题评分或反复使用开发样本 | 对照任务、留出样本、独立核查；不虚构效果 |

**必要的安全、隐私和授权边界不属于应删除的“污染”。**

## 6. 两个微型分类演示
### 示例 A：March 1991「探索/利用」的权衡
- 主要问题：P6 决策和下一步行动；相关 P3 搜索。
- 学科：组织学习/管理学；对象：原始论文中的理论观点。
- 可靠性：可核验原文存在，**不能证明固定的探索/执行比例适合 AI**。
- 与 ai-d 的关系：当研究不断增多却没有交付时，可拿它作为反思线索；不能直接规定每次搜索多少轮。

### 示例 B：W3C SKOS 的 broader/narrower/related
- 主要问题：P4 知识组织；相关 P8 同义概念噪音。
- 学科：图书情报学/语义网标准；对象：概念表示方法。
- 可靠性：W3C 标准可核验；不证明模型一定能因标签变得更聪明。
- 与 ai-d 的关系：把“搜索/检索/信息获取”等术语明确上下位或关联，减少重复文件；效果应比较实际查找和调用质量。

## 7. 公开仓库约束
ai-d 当前是 **Public**，因此仅放合法可公开的原始来源链接、自己的知识提炼、不识别个人的抽象案例和可披露的对照结果。不要复制私人会话全文、敏感个人材料、密钥、收费书籍正文或未经授权的版权内容。

## 8. 下一次应如何证明管理方式更好？
首先从仓库既有五份研究记录中抽取10条可核查主张，用同一问题入口和元数据分类，检查：
- 能否更快找到相关来源；
- 能否识别过时或无关的知识；
- 是否减少内容重复和错误关联；
- 是否能指出哪条知识真正改变了答案或实施选择。

这是一项**待执行的诊断实验**，不是已经证明知识管理 V0.2 优于 V0.1 的结论。

## 2026-11-07｜理论互证与初步通过（不等于生产实跑）

新增的认识依据：[理论稳健性、溯因、三角互证与设计科学研究](../../research/2026-11-07-theoretical-triangulation-provisional-acceptance.md)。

- **允许有依据的积极阶段结论**：成熟理论、不同假设的推演、原创研究、可核查源码和已发表的相关实验可互相约束，足以支持“理论上成立/有条件可信/值得采用为低风险研究方法或可逆方案”。不因“ai-d 未独立 A/B”就把该理论结论整项打成 UNKNOWN；也不要求每轮必须现场实跑。
- **定位具体未确定的地方**：例如“方案理由有理论和上游资料支持；ai-d 中的真实收益尚未测量”，而不是把前半部分一并否定；有合理机制的异常/机会候选应允许继续调查，不因尚未证明最终身份或收益而一律漏报。
- **检验相互支持是否有新增内容**：多个 AI 角色说法一致可能重复同一资料与错误；关注不同假设、跨现象预测、独立证据、竞争解释及其关系。形式推导仅保证前提成立时的逻辑后果，不保证现实前提正确。
- **按主张与现实后果追加验证**：学习/解释/可逆研究可先理论初步通过并继续；声称具体软件已部署、真实绩效提升或现实高风险事实，需要对应的实测与授权。理论依据可指导验证重点，而非阻止行动或替代验收。

这些是已有 P2/P5/P6/P7/P8 的判断修订，**不是新证据等级制度或强制门禁**；不要强制为每条普通知识写大量状态注释。

## 2026-11-07｜实质研究的保存—回读—续研约定

当工作目标是长期研究，并且已经产生新的、有证据的认识时，**研究结束后在开始新一轮前**：
- 检查与当前问题相关的既有原始文件、已确认目标、争议与未解处，防止重复建档或擅自替换；
- 优先修订原位置；只有新研究问题有独立证据和持续价值时，才创建单独研究记录；
- 保存来源、研究方法、证据级别、竞争解释、哪些旧判断被修正、尚不能确认什么；将新研究从既有 P1–P8 入口连接；
- GitHub 提交后回读实际文件，核对内容与链接。失败则报告失败，不以“已准备内容”声称已保存；
- 从记录中**最能改变下一项判断**的未解问题继续研究，而不是为了轮次或文件数量重复搜索。

适用范围：实质研究成果的长期沉淀；**不适用**于普通问答，也不是所有任务的强制步骤。保留用户重大目标的决定权、公开仓库隐私和版权约束；本约定仅是研究维护办法，不能证明 ai-d 已实现自动续研或能力提升。


## 2026-11-09｜纯理论知识不能等待功能落点才算值得吸收

**修正前提**：外部项目里的理论、概念、隐喻、研究方法、经验性判断与未解决矛盾具有独立的知识价值。若只保留“能转成代码/指标/产品决策”的资料，会系统性排除尚未有用例但可能推翻当前目标认知的新思想。**知识是否值得理解**与**是否值得作为程序规则运行**是两个不同判断。

此次 [Blix 在原有正文的纯知识转换](https://github.com/sunshihao001/grok/blob/blix/knowledge/README.md) 用三个不同的对象验证“不是仅打标签”：Hermes 的字段四问转为一般的观测/认识论方法；旧五力模型转为“调查价值与交易价值分叉”的市场经济认识；meme 的AVWAP/FCZ概念转为“参照点选择与事前/事后可得性”的解释问题；qb的防假完成转为“工作状态、判断依据、现实增益”三种不同的验收命题。这里所谓验证仅指**来源可定位、转换结果已保存且逻辑差异可审查**，不代表模型测量有提升。

### 独立的四类知识命运（不是固定流程）

- **原文值得保全**：保留它原来回答的问题、术语在作者语境中的意思、不同版本及内部争议，不为适配当前产品强行改写；不要求把所有全文注入主上下文。
- **已有认识可以同化**：将经审查且不重复的原则放入现有唯一专业正文，明确它与原概念的同异、哪一层解释被修订。若与已知知识相同，只增加来源与反例，不新造卡。
- **纯研究尚无应用**：对于暂时找不到产品功能、但解释力和探索潜力明确的概念，作为独立研究命题、学科联系或待验证观点继续保留，**不能因没有代码用途就标成低价值**。是否继续深入取决于信息价值与可推翻性。
- **存在失败与冲突**：未经校准的概率/阈值、指标偷换、时间泄漏等不应因“源头历史很宝贵”原样升级为真值；应保留作者原主张及反例，把修正后的可成立原理单独讲清。

### 来自跨行业认知的非平凡问题

一个旧项目声称“多指标结合能提高准确性”，核心不是有多少标签，而是：指标是否由同一个上游变量生成、样本是否事后选择、缺失是否非随机、决策的损失函数是什么。类似问题可以迁移到财务预警、医疗筛查、制造质量控制与市场异常研究，但**不同应用的风险偏好与数据语义不能迁移**。旧Hermes “缺数据→BLOCK”对交易保护的用途，不可照搬为只读研究“缺数据→不调查”。

**检验方式**：给定同一原始知识，比较只存名称/链接、全文堆叠、按本意深度转换且保留异议的三个条件。评价是否发现此前未知的正确问题、修正原结论、改变对应调查和适用范围，另核查误报、Token成本与用户介入。尚未执行受控模型A/B，不自称ai-d已完成知识激活。
